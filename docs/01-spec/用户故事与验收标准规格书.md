## 1. 文档契约与全景索引

### 1.1 核心原则（v4.6）

- **本地优先，信任用户**：所有数据处理在端侧完成，不主动模糊/删除用户媒体内容，隐私控制权完全归属用户。
- **主动智能，情境感知**：从被动检索升级为“地理围栏唤醒 + 情绪干预 + 创作生成”三位一体的主动回忆引擎（去时间条件，围栏重置仅基于离开再进入）。
- **多源融合，跨域关联**：支持 P0/P1/P2 三级数据源分层接入，实现跨 App、跨模态、跨时间的语义关联。
- **透明可控，反馈闭环**：后台任务、数据处理、权限控制全程可视；用户反馈纯本地记录，应用时间衰减及手动重置/撤销。
- **数据主权绝对化**：所有记忆永不自动过期；删除路径强制用户确认；排除项恢复需显式操作；原始文件删除级联清除所有副本（不写入 ExcludedAssets，但会清理无效排除记录）。
- **模型策略封闭化**：禁止用户切换模型；唯一索引与内置模型强绑定；加载失败仅提供手动重试（重试本地已有模型），App 内不主动发起网络下载。
- **语言策略明确**：仅支持简体中文（zh-Hans）和英文（en-US），不支持繁体中文及方言。
- **ExcludedAssets 写入规则**：仅用户主动选择“仅从 Echo 移除”时写入；系统自动删除（如变更同步中的旧记忆删除）**不写入**；原始文件级联清除**不写入**但会清理对应排除记录并提示用户；重新授权后提供一键恢复排除项选项（仅限当前数据源）。
- **反馈阈值策略**：仅当查询与记忆的余弦相似度 ≥0.80 时应用反馈权重，确保学习效果集中在高度相关场景。单条记忆的反馈权重调整上限为 ±0.5（截断）。
- **低电量模式行为**：提供独立开关，开启后自动暂停后台任务以省电；关闭时即使系统低电量模式也不暂停（用户可选择优先性能）。

### 1.4 全 App 平衡画布展示决策（跨故事 UI 约束，2026-08-31）

> **决策人**：Human product owner；方案 B「平衡画布」适用于 Echo 全部页面。本节只约束展示与交互一致性，不改变任何 Pipeline、权限、隐私、排序、删除或审计 AC。

1. AppShell、Home、Search、Detail、Settings、Onboarding、Awakening、BackgroundTask、Creation、Degradation、ResumeProgress、Translation 必须使用同一 `echo-memory-canvas` design profile。AppShell 是承载三类 Surface 的系统宿主，不归类为 Task surface，也不创建第四种 family。
2. 所有页面共享系统 Dynamic Type、semantic colors、warm restrained accent、统一 spacing/radius、SF Symbols、内容容器层级、主要/次要动作语义与 Reduce Motion 行为；禁止功能域自建第二套视觉 token。Warm accent 固定为语义色对：`warmAccent` 在浅色外观使用 sRGB `#A64B32`、深色外观使用 sRGB `#E08A68`；`onWarmAccent` 分别使用 `#FFFFFF` 与 `#1C1C1E`。重点 action 必须同时消费背景色与对应前景色，不得硬编码同一前景色覆盖两种外观。
3. Discovery surfaces 以图片优先、非等高内容节奏和连续探索表达方案 B；Focus surfaces 使用同源的单列媒体、引用卡片与 grouped metadata；Task surfaces 使用同源的 grouped system containers、状态组件和动作层级。
4. 风格一致不等于布局相同：masonry 仅用于符合阈值的 Discovery，Focus/Task 明确禁止 masonry。NavigationStack、TabView、search、Form、List、Sheet、Alert 等系统交互语义保持 Apple 原生。
5. 相同语义必须复用相同视觉组件；页面级验收同时检查 surface family 正确性和全 App profile 一致性，任一不满足均不通过。
6. 禁止复制 Pinterest 的名称、商标、品牌色、文案、控件、手势或可识别 trade dress。
7. “约 60% Pinterest-inspired + 40% Apple 原生”仅用于描述方向，不是逐页面比例或验收数字；验收只依据本节、Surface Contract、共享 token/component 身份、系统行为和可访问性结果。
8. Phase 4 `4.0b` 只改造 Detail、Creation、Translation 的 Focus 表现与交互连续性：单列主内容、真实媒体或诚实不可用态、可点击引用、grouped metadata、原文/译文关系和系统 share/export。它不新增 Core 写入语义，也不得用 Preview/fixture 成功态声称编辑重索引、冲突持久化、原始来源删除或 Notes 保存已在生产完成。
9. Focus 生产验收必须从真实 Home/Search 路由进入具体记忆，保持系统返回栈与稳定 MemoryID；无来源、已撤权、媒体不可解析或生产 mutation boundary 缺失时必须显示诚实降级/不可用状态，不得回退到 bundled sample、伪造内容、伪造成功 Toast 或假链接。
10. Phase 3/3F 证据中仍为 Partial 的 Focus 生产行为按 ADR-017 拆分交付：`4.0e` 负责编辑、重新向量化与持久冲突；`4.0h` 负责真实来源解析及 PhotoKit 原始资产删除 saga；`4.0i` 负责可验证引用、稳定 Detail 路由与系统分享审计；`4.0j` 负责月度/年度报告的持久 earliest-eligible 调度。`4.0b` 只提供诚实表现，`4.2` 只验证闭环；两者都不得替代生产实现。
11. Phase 4 `4.0c` 只改造 Settings、Onboarding、AwakeningSettings、BackgroundTask、Degradation、ResumeProgress 的 Task 表现：共享 grouped background、section header、status/action components、semantic color、spacing、radius 与 motion，并继续使用系统 Form/List/Sheet/Alert/confirmationDialog。它不得新增或改变 Core、数据库、权限、同意、任务调度、恢复、迁移、删除或审计语义，也不得以 fixture/Preview 成功态证明生产行为。
12. 首次体验遵循渐进式权限：PIPL 同意必须先持久化成功，随后才能显示或执行任何受保护数据请求；持久化失败停留在可重试错误态。相册权限只在用户明确选择 `Connect Photos` 后请求，主动选择 `Not Now` 直接继续且不打开系统设置；只有系统返回 denied/restricted 后才提供用户发起的设置恢复。通知是独立投递 opt-in，不由 geofence/emotion/anniversary 开关隐式请求，也不作为 App 内唤醒卡生成的总开关。geofence 首次启用只请求 When In Use；若用户需要 App 被终止后仍可区域唤醒，在解释能力差异后以第二个明确动作请求 Always。HealthKit 只请求 HRV 读取；因系统不披露读取授权结果，UI 只显示 not requested/request completed/unsupported 与可读样本结果，不显示伪造的 granted/denied。三个唤醒偏好、通知投递意图与 HealthKit request lifecycle 在本地 SQLite 持久化；系统授权状态每次从系统读取，禁止复制为第二份真相。拒绝或跳过任一可选权限不得阻止进入 App，也不得循环催促；打开 App 或设置页只读状态，不触发系统 prompt。
13. Phase 3/3F 证据中仍未完成的 Task 生产行为不得由视觉任务或后续测试冒充：渐进式权限与按功能 opt-in 由 `4.0f` 交付；保存进度后的任务重建、继续/重新开始与重启恢复由 `4.0g` 交付。`4.0c` 只提供诚实状态和动作层级，`4.2`/`4.4` 只消费并验证这些闭环。
14. Settings 中的设备迁移入口遵循 US-SRC-007、ADR-008 与 ADR-010：允许用户中介的固定格式加密迁移包经 AirDrop/系统分享传输，以及 Finder/iTunes 加密本地备份恢复；迁移包永不包含原始照片、视频、备忘录或语音文件。不得继续把“禁止导出全部原始记忆数据”误写为“禁止任何迁移包”。

## 2. 数据源接入模块（13 Stories）

### US-SRC-001：P0 数据源接入（图片+视频+备忘录+语音备忘录）

- **优先级**：P0

- **用户故事**：作为用户，我希望 Echo 能接入我主动创作的图片、视频、备忘录和语音备忘录，作为第一人称叙事的核心数据源。

- 验收标准

  ：

  1. 使用 PHAsset 读取图片/视频（PhotoKit 授权范围）；备忘录与语音文件通过 **Share Extension 显式分享**摄入（R-5.2 路径 A，2026-08-01 决策——iOS 公开 API 不支持自动读取系统备忘录/语音备忘录）。Share Extension 不可靠暴露 host App 身份，因此 Echo 只记录 `importOrigin=shareExtension` 与实际 `contentType`；没有可信元数据时不得把分享内容猜测为 Notes 或 Voice Memos。
  2. 所有数据源摄入均在端侧完成，不上传云端。
  3. 权限请求文案清晰说明用途，支持“仅授权部分相册”。PIPL 同意必须持久化成功后，只有当用户明确选择 `Connect Photos` 时才请求 PhotoKit `.readWrite` 权限；用户选择 `Not Now` 时不调用 PhotoKit，直接继续。系统返回 limited/full 时按实际授权范围工作；返回 denied/restricted 时显示可跳过说明，只有用户主动选择恢复授权时才提供系统设置入口。拒绝或跳过后仍可通过 Share Extension 使用备忘录/语音备忘录，不得在首次启动流程中反复请求。
  4. 首次授权相册后触发全量后台索引，进度可在实时后台任务面板（US-SYS-001）中查看。备忘录/语音备忘录仅分享后逐条摄入（无后台全量索引）。
  5. 审计记录 `.dataSourceConnected`，含 `sourceType`、`itemCount`。
  6. 仅处理已下载到本地的资源（使用 `PHImageManager` 的 `requestImageData` 且 `options.isNetworkAccessAllowed = false`，若返回 nil 则表示未下载；家庭共享相册同理，不区分来源）。**在首次授权相册时，增加提示**：“为了完整记忆，建议将 iCloud 照片设置为‘下载并保留原件’或在使用 Echo 前手动下载。已优化存储的照片可能无法被 Echo 识别。” 提示中增加“前往设置”按钮，使用 `UIApplication.openSettingsURLString` 跳转到系统设置（如照片权限设置）。若无法跳转，兜底仅提供文本说明。
  7. 用户可以通过编辑记忆卡片（US-AWK-007）为图片/视频补充文字描述，这些描述将参与向量化。

### US-SRC-002：P1 数据源接入（日历+位置+HealthKit+iMessage+邮件）

> 🔧 **AC 修订（Phase 3F / ADR-006，2026-08-04）**：iMessage 自动历史读取移出 v1（MessageUI 无公开 API 读取历史；SRC-002 中该条为 spec-invalid）。v1 范围保留日历（EventKit）、位置（CoreLocation）、健康（HealthKit，仅情境触发不存储原始数值）数据源；邮件自动读取同样不进入 v1。

- **优先级**：P1

- **用户故事**：作为用户，我希望 Echo 能接入日历、位置、健康、短信和邮件数据，为静态记忆提供时空-生理-社交情境层。

- 验收标准

  ：

  1. 使用 EventKit 读取日历/提醒，CoreLocation 读取位置，HealthKit 读取健康数据（仅用于情境触发，不存储原始数值），MessageUI 读取 iMessage，MailCore 读取邮件。
  2. 每项数据源独立授权开关，支持按时间范围/内容类型精细控制。
  3. iMessage/邮件仅读取用户明确授权的会话/文件夹。
  4. 审计记录 `.contextSourceConnected`，含 `sourceType`、`authorizationStatus`。

### US-SRC-003：P2 数据源接入（浏览器+第三方 App Share Extension）

- **优先级**：P2

- **用户故事**：作为用户，我希望通过 Share Extension 手动将浏览器内容或第三方 App（微信/小红书等）内容导入 Echo，永不自动抓取。

- 验收标准

  ：

  1. Share Extension 支持文本/图片/链接/文件。
  2. 导入前预览确认，用户可选择标签/备注。
  3. 第三方数据标记 `source=thirdParty`，不参与自动情境触发；来源 App 不可可靠识别时保持 `unknown`，不得通过扩展自身 bundle ID、文件名或内容启发式伪造来源。
  4. 审计记录 `.shareExtensionImported`，含 `importOrigin=shareExtension`、`contentType`；仅当系统公开 API 或用户明确选择提供可信来源 App 身份时，才附加 hash-only `sourceAppDigest`。

### US-SRC-004：后台自动导入控制（有开关）

- **优先级**：P1

- **用户故事**：作为用户，我希望可以控制是否允许系统在后台静默导入新数据。

- 验收标准

  ：

  1. 设置页提供“后台自动同步新数据”开关，默认开启。
  2. 开关关闭时，仅在 App 处于前台时触发增量同步。
  3. 导入前必须校验 `ExcludedAssets` 表，跳过所有已排除资源。
  4. 后台导入任务遵循 iOS Background Tasks 规范，可被系统随时挂起。
  5. App 前台时通过“实时后台任务面板”显示导入进度及状态。
  6. 审计记录 `.autoImportCompleted`，含 `newItemCount`、`failedCount`、`excludedCount`。

### US-SRC-005：未导入数据检测与手动补导

- **优先级**：P1

- **用户故事**：作为用户，我希望可以控制定时检测开关，并可手动触发检测；检测结果仅展示，由我决定是否导入。

- 验收标准

  ：

  1. 设置页提供“定期扫描遗漏数据”开关（默认关闭）及“立即扫描”按钮。
  2. 扫描结果页以列表形式展示未导入项，支持全选/单选。

### US-SRC-007：设备迁移（本地加密用户中介传输，增加批量冲突选项）

- **优先级**：P1

- **用户故事**：当我换新 iPhone 时，我希望 Echo 的 canonical 记忆数据、设置和索引身份能通过本地加密迁移包或加密备份恢复完整迁移，无需上传云端；如果目标设备已有数据，应提示我选择覆盖或合并，并在冲突时提供批量处理选项。

- 验收标准

  ：

  1. 迁移方式仅限：固定格式加密 Echo 迁移包经 AirDrop/系统分享进行用户中介传输，或 Finder/iTunes 加密本地备份恢复；**不使用 iCloud CloudKit 同步、密钥服务器或远程恢复**。迁移包使用 ADR-008/ADR-010 规定的 `AES-GCM-256+HKDF-SHA256`，一次性传输密钥与包分离交付且会话结束销毁。

     - 若无数据，直接恢复。
     - 若有数据，弹窗提示用户选择“**覆盖**”（删除目标设备原有数据，替换为源设备数据）或“**合并**”（保留两边独有的记忆）。对于相同记忆 ID 的冲突项，提供冲突解决界面，显示冲突总数，并允许用户选择“批量应用”：全部使用源设备版本 / 全部使用目标设备版本 / 两者都保留。同时支持逐项自定义。

### US-SRC-012：数据源内容变更的自动同步（前台检测，优化哈希跳过条件，策略仅开始判断）

- **优先级**：P1

- **用户故事**：当我在系统相册中编辑照片、修改备忘录内容、更新日历事件等时，我希望 Echo 能自动同步这些变更，保持记忆最新；对于已变更的内容，应删除旧记忆并创建新记忆（或整体替换），同时我可以控制是否开启此功能。

- 验收标准

  ：

  1. 监听系统通知：`PHPhotoLibraryChangeObserver`、备忘录更新（`lastUsedDate` 变化后强制全量哈希对比）、日历变更（**改为在 App 前台时对比日历库的 `lastModified` 时间戳**，`EKEventStoreChangedNotification` 仅作为辅助加速刷新）。
  2. 检测优化：对备忘录等先检查 `lastUsedDate`，若改变则进行全量哈希对比，确认真实修改后才触发同步。**在同步开始时判断一次**：若备忘录内容超过 **100KB** 或设备**可用内存低于 300MB** 或设备总内存 ≤2GB，则使用“修改时间戳 + 文件大小”组合判断跳过哈希对比，并在审计记录中标记 `.hasHashSkippedDueToConstraints`。同步过程中不因内存变化而切换策略。
  3. 设置页提供“后台自动同步数据源变更”开关，默认开启。
  4. 开关开启时，检测到变更后触发后台 `BGAppRefreshTask` **增量替换**：先删除旧记忆（包括向量、索引、缓存、元数据），再重新摄入新内容，保持记忆 ID 不变或建立新关联。**系统自动删除旧记忆时不写入 `ExcludedAssets` 表**。
  5. 增量更新必须校验 `ExcludedAssets` 表，跳过已排除资源。
  6. 冲突处理：若后台同步过程中用户尝试手动编辑同一条记忆（US-AWK-007），应**阻止用户保存**，并显示提示“该记忆正在同步更新中，请稍后再编辑”，参考统一错误响应矩阵 L4 数据冲突级别。
  7. 变更同步进度通过“实时后台任务面板”展示。
  8. 开关关闭时，仅在 App 前台手动触发检测（见 US-SRC-013）。
  9. 审计记录 `.dataSourceChangeSynced`，含 `changeType`、`sourceType`、`affectedCount`、`replacedFlag=true`、`excludedNotWritten=true`、`hashSkipped`。

### US-ING-006：存储事务一致性保障

- **用户故事**：作为用户，我不希望出现“向量存在但原文丢失”或“原文存在但无法检索”的数据不一致情况。

- 验收标准

  ：

  1. 向量写入与原文/元数据写入在同一数据库事务中（允许使用两阶段提交或补偿回滚，最终保证一致性）。
  2. 任一写入失败则整体回滚，无残留数据。
  3. FTS5 索引更新与主事务同步提交。
  4. 故障注入测试验证回滚正确性。
  5. 审计记录 `.ingestTransaction`，含 `rolledBack=true/false`。

## 4. 跨语言检索模块（8 Stories）

### US-RET-001：英文查询匹配中文记忆

- **优先级**：P0

- **用户故事**：作为英语用户，我希望用英文提问能从中文记忆中检索到相关内容。

- 验收标准

  ：

  1. 查询向量与中文记忆向量余弦相似度 ≥0.7。
  2. Cross-Encoder 精排后进入 Top-K。
  3. 结果标记 `crossLanguageMatch=true`、`sourceLanguage=zh-Hans`。
  4. 审计记录 `queryLanguage=en-US`、`resultLanguages=[zh-Hans]`。
  5. Recall@10 ≥85%（Golden Dataset）。

### US-RET-002：中文查询匹配英文记忆

- **优先级**：P0
- **用户故事**：作为中文用户，我希望用中文提问能从英文记忆中检索到相关内容。
- **验收标准**：同 US-RET-001，语言方向相反；中文分词不影响向量生成质量。

### US-RET-003：混合语言查询处理

> 🔧 **AC 修订（Phase 3F / ADR-006 + ADR-009，2026-08-04）**：查询向量使用 **E5 384d 文本空间**（非 CLIP 空间）：混合语言查询经 E5 编码后检索文本与视觉双通道并按 RRF 融合；删除对 CLIP 空间直接对齐的要求。

- **优先级**：P1

- **用户故事**：作为双语用户，我希望用中英混合的句子提问，系统能正确理解并检索。

- 验收标准

  ：

  1. 语言检测标记为 `mixed`，不强制归类单一语言。
  2. 各通道使用原生查询表示——E5 384d 文本空间与配对 SigLIP2 文本塔 768d 视觉空间；通道排名经 canonical `memoryId` RRF 融合（WP0/ADR-015 修订：canonical-id-fusion-before-rrf），不跨空间比较或相加原始分数。
  3. 检索结果包含中英文记忆，按语义相关性排序。
  4. 审计记录 `queryLanguage=mixed`。

### US-RET-004：多维元数据过滤（时间/标签/地点/人物）

> 🔧 **AC 修订（Phase 3F / ADR-006，2026-08-04）**：移除人物维度——人物 ID 已随 US-SRC-006 移出 v1（PHAsset 无 People 身份 API）；v1 过滤维度限定为时间/标签/地点等可行维度，人物过滤在 v1 后人物身份管线获批后再引入。

- **优先级**：P0

- **用户故事**：作为用户，我希望通过时间、标签、地点范围、人物等多维度缩小检索范围，提高精准度。

- 验收标准

  ：

  1. FTS5 预过滤候选集，支持 `timeRange`、`tags`、`geoRadius(lat,lon,km)`。
     > ⛔ `personIds` 过滤已移除（R-5.3：US-SRC-006 v1.0 延后）。
  2. ~~人物过滤使用 US-SRC-006 同步的人物 ID。~~（R-5.3 移除）
  3. 地点过滤使用 CoreLocation geohash 索引。
  4. 过滤后 ANN 检索 P95 延迟降低 ≥30%。
  5. 审计记录 `.retrieval` 含 `filterApplied=true`、`filterDimensions=[time,person,geo]`。

### US-RET-005：多轮追问

> 📌 **实现状态（3F.6，2026-08-11）**：AC-4 已实现——同一查询复用判定 + 审计 `.followUpQuery`（sourceLanguage 含 `parentTraceId`、`rewrittenQuery` 查询 SHA-256 摘要）。**AC-1（对话历史 FIFO ≤10 轮）与 AC-2（追问自动注入上轮 `memoryIds` 隐式过滤）未在 3F.6 落地**——production `SearchPipeline` 仅追踪单轮 `lastSearchQuery`/`lastSearchTraceID`（方案 a），见 DEF-58-002。**AC-3（LLM 生成追问改写查询）延后至 DEF-58-001**：Echo 为完全离线运行时（ADR-009），无生成式 LLM 可落地；方案 a（历史 + memoryIds 隐式过滤，不生成改写查询）已获用户 2026-08-11 确认（AC-1/AC-2 方案 a 实际只实现单轮追踪）。

- **优先级**：P1

- **用户故事**：作为用户，我希望基于上一次搜索结果继续提问（如“那天的天气怎么样？”“还有谁在场？”），系统能理解上下文。

- 验收标准

  ：

  1. 对话历史 ≤10 轮，超出按 FIFO 截断。
  2. 追问查询自动注入上轮结果的 `memoryIds` 作为隐式过滤。
  3. LLM 生成追问改写查询，再送入 Retriever。
  4. 审计记录 `.followUpQuery`，含 `parentTraceId`、`rewrittenQuery`。
  5. 新会话清空历史，不跨会话泄漏。

### US-RET-006：跨语言低置信度透明降级

- **优先级**：P1

- **用户故事**：当跨语言匹配不确定时，我希望系统明确提示而非静默返回低质结果。

- 验收标准

  ：

  1. Cross-Encoder 分数 <0.6 标记 `.lowConfidence`。
  2. UI 显示置信度提示文案，统一为：“以下结果相关性较低，建议优化关键词或尝试不同表述。”（本地化 zh-Hans/en-US）。
  3. 结果仍返回，不被过滤。
  4. 提供“不准确”反馈按钮（仅本地学习）。
  5. 审计记录 `alignmentScore`、`fallbackReason`。

### US-RET-007：检索结果缓存与策略感知失效

> 📌 **实现状态（3F.6，2026-08-11）**：已实现——`SearchResultCacheActor` 缓存键包含 `policyVersion`、`modelVersion`、`queryHash`，TTL 由 UserPolicy 定义（默认 1h），policy 版本变更自动失效对应条目。

- **优先级**：P1

- **用户故事**：作为用户，我希望重复查询能快速返回，但隐私策略变更后缓存立即失效。

- 验收标准

  ：

  1. 相同查询+相同策略版本命中缓存，P95 <100ms。
  2. UserPolicy 版本号变更，旧缓存自动失效。
  3. 缓存 TTL 由 UserPolicy 定义，默认 1h。
  4. 缓存键包含 `policyVersion`、`modelVersion`、`queryHash`。
  5. 审计记录 `.cacheHit=true/false`。

### US-RET-008：检索超时与部分结果返回

> 📌 **实现状态（3F.6，2026-08-11）**：已实现——`GenerationRoutedChannelAdapter` 通道超时返回 `timedOut=true` 的部分结果，不阻断其他通道；空索引 generation 同样降级为 timedOut 部分结果（partial results 语义），L3 路由缺失以 `error`（`.generationRouteMissing`）区分（DEF-34-002）。

- **优先级**：P1

- **用户故事**：当检索耗时过长时，我希望先看到部分结果，而非无限等待。

- 验收标准

  ：

  1. ANN 检索超时阈值 =2s，超时返回已获取结果。
  2. UI 显示“结果可能不完整”提示。
  3. 超时结果标记 `.partialResults=true`。
  4. 审计记录 `.retrievalTimeout`，含 `returnedCount`、`elapsedMs`。
  5. 超时阈值可由 UserPolicy 配置。

## 5. AI 响应与创作模块（8 Stories）

### US-SYN-001：首选语言受控输出（与 UI 语言统一，仅支持简中/英文）

- **优先级**：P0

- **用户故事**：作为用户，我希望 AI 响应语言始终与 App UI 语言一致，无需单独设置；系统仅支持简体中文和英文。

- 验收标准

  ：

  1. `preferredLanguage` 自动同步自 `Locale.current.languageCode`，只允许 `zh-Hans` 或 `en-US`。
  2. 若系统语言为繁体中文或其他方言，默认映射为 `zh-Hans`，并在**首次启动时提示一次**“Echo 当前仅支持简体中文和英文，将使用简体中文显示”，之后不再提示。
  3. Prompt 显式注入当前 UI 语言。
  4. Language Aligner 检测响应语言，首次匹配率 ≥99%。
  5. 不匹配时重试 1 次，重试成功率 ≥95%（引用统一错误矩阵 L1）。
  6. 审计记录 `outputLanguage`、`uiLanguage`、`languageRetryCount`。

### US-SYN-002：溯源锚点展示（杜绝幻觉）

> 🔧 **AC 修订（Phase 4 / ADR-017，2026-09-03）**：来源必须由生成结果显式返回并在本次输入集合内校验；禁止按段落序号轮询分配 MemoryID。未知、缺失或失效来源统一标记 `NoSource`。

- **优先级**：P0

- **用户故事**：作为用户，我希望 AI 回答中每条事实都附带可点击的原始数据链接（照片/视频/备忘录/健康数据/…），确保有据可查。

- 验收标准

  ：

  1. 每个事实段落必须携带生成协议显式返回的一个或多个 source MemoryID；解析器仅接受本次检索输入集合中的稳定 ID，并渲染 `[🔗 MemoryID:xxx]` 锚点。禁止按段落顺序、数组位置或默认首项猜测来源。
  2. 点击锚点时重新校验当前 UserPolicy 与 source resolver；来源仍获授权且可解析时跳转至稳定 MemoryID 对应的 Echo 详情页，撤权、资产消失或不可解析时显示诚实不可用状态。
  3. 无来源、未知 ID、ID 不在本次输入集合或校验失败的陈述标记 `[⚠️ NoSource]` 并置灰，且禁用跳转。
  4. 锚点样式与正文区分，支持长按预览。
  5. 审计记录 `.synthesis` 含校验后的 `citationCount`、`noSourceCount`；MemoryID 仅记录摘要，不记录生成原文。

### US-SYN-003：情感内容生成（事实依据+创作）并保存到备忘录

> 🔧 **AC 修订（Phase 3F / ADR-013，2026-08-04）**：Notes 交接**仅通过系统 share/export（用户中介）**；禁止 `notes://echo/...` 深链与私有 NoteStore 直写（SYN-003 原 AC 中直接创建备忘录的条目为 spec-invalid）。

- **优先级**：P1

- **用户故事**：作为用户，我希望基于过去多年的日记和照片，生成“给未来孩子的信”或“年度焦虑与治愈报告”等有事实依据的情感内容，并通过系统分享面板交接到 Apple Notes 或其他用户选择的目标。

- 验收标准

  ：

  1. 支持预设创作模板（信件/报告/诗歌/时间线）。
  2. 生成内容严格引用检索结果，每段附溯源锚点。
  3. 支持文字预览、复制、导出为 PDF/Markdown。
  4. 生成结果页提供“保存到备忘录”入口；点击后生成本地导出内容并呈现系统 share sheet，由用户选择 Apple Notes。Echo 不调用私有 NoteStore、不使用 `notes://` 深链，也不假定用户最终选择了 Notes。
  5. Echo 只确认导出内容已准备并成功呈现系统 share sheet；不得显示“已保存到 Notes”、伪造笔记链接或把用户取消分享记为失败。导出内容准备或 share sheet 呈现失败时按统一错误矩阵 L2 处理（Toast + 重试按钮）。
  6. 生成完成时审计记录 `.creativeGeneration`，含 `templateType`、`sourceMemoryCount`、`citationCount`、`noSourceCount`；本地导出准备完成且系统 share sheet 成功呈现后另记 `.creationSharePresented`，含结构化 `exportFormat`、`sharePresented=true`。准备或呈现失败时记录 `sharePresented=false` 并按 L2 处理。不得记录或推断目标 App、用户是否完成保存或生成内容原文。

### US-SYN-004：月度/年度叙事报告自动生成并保存到备忘录

> 🔧 **AC 修订（Phase 3F / ADR-006 + ADR-012，2026-08-04）**：自动生成采用 **earliest-eligible / best-effort 窗口**，不保证精确后台时刻（iOS 后台调度限制，SYN-004 原 AC 中『精确后台生成』为 spec-invalid）。
>
> 🔧 **生产边界补充（Phase 4 / ADR-017，2026-09-03）**：报告调度必须持久化周期键并幂等执行；fixture 的报告标题或分享 UI 不构成自动生成证据。当前不可用的人物身份或健康输入必须省略并标注，不得伪造。

- **优先级**：P1

- **用户故事**：作为用户，我希望 Echo 每月/每年自动生成结构化叙事报告，关联事件、情绪曲线、关键人物与生理状态，并可一键保存至 Apple Notes。

- 验收标准

  ：

  1. 月报在每月 1 日后、年报在每年 1 月 1 日后的最早可用执行机会生成（可关闭）；App 启动、进入前台或系统提供后台执行机会时处理尚未完成的最早符合周期。每个周期使用持久幂等键，最多成功生成一次，不承诺精确后台时刻。
  2. 报告按实际可用且已授权的数据包含事件链、情绪趋势、人物摘要与 HealthKit 摘要；任何类别不可用时省略该分区并明确标注。禁止用 fixture、占位人物或伪造健康数据补齐固定版式。
  3. 所有数据点附溯源锚点。
  4. 支持分享/导出/打印。
  5. 报告生成页提供“保存到备忘录”入口，交接逻辑与 US-SYN-003 的系统 share/export 边界一致，导出标题自动包含报告周期。
  6. 报告生成后审计记录 `.narrativeReportGenerated`，含 `periodType`、实际 `dataSourcesUsed` 与周期幂等键摘要；系统分享另记 `.creationSharePresented`，含结构化 `sharePresented`。不推断用户最终选择的目标 App 或保存结果。

### US-SYN-005：私有 Prompt 模板（滑动窗口，分析范围包括查询和感受，感受删除后下次更新体现）

- **优先级**：P2

- **用户故事**：作为用户，我希望 Echo 根据我**近期**的语言风格和关注点，自动生成个性化的系统提示词，让 AI 更懂我；且我可以控制分析的时间窗口。

- 验收标准

  ：

  1. 分析范围包括：**用户的所有查询字符串、用户对卡片记录的感受（US-AWK-005）**。不包括备忘录原文。分析最近 **N 天**（默认 N=30）内的上述数据，提取风格关键词与高频主题。超过窗口的老数据不参与个性化，但不会被删除。所有分析均在本地完成，原始数据不离开设备。
  2. 分析频率：每日凌晨触发一次，或用户调整窗口时立即触发。每次分析最多处理最近 500 条记录。
  3. 设置页允许用户调整窗口大小（可选值：7/14/30/60 天），调整后立即重新生成 Prompt。
  4. 生成个性化 System Prompt 草稿，用户可编辑确认。
  5. 确认后注入后续所有合成请求。
  6. 支持重置为默认 Prompt。
  7. **当用户删除某条感受时，个性化分析将在下一次定时任务（每日凌晨）或用户手动重置 Prompt / 调整窗口时体现，不立即更新。**
  8. 若用户使用时间不足窗口天数，则分析所有可用数据。
  9. 审计记录 `.personalPromptUpdated`，含 `windowDays`、`styleKeywords`、`userEdited`、`analyzedRecordCount`。

### US-SYN-006：情绪干预模式

- **优先级**：P1

  4. 不提供未经请求的建议，以倾听为主。
  5. 审计记录 `.emotionalInterventionTriggered`，含 `detectedEmotion`。

### US-SYN-007：领域术语一致性

- **用户故事**：作为用户，我希望 AI 提到的功能名称与界面文字完全一致。

- 验收标准

### US-SYN-008：合成失败模板降级

  5. 审计记录 `.synthesisFallback`，含 `failureReason`。

## 6. 主动唤醒与交互模块（7 Stories）

### Home/Search Discovery 展示细则（1.4 全 App 决策的 Discovery 子集）

> 本节只约束 Home/Search 对 US-AWK-002、US-AWK-005、US-RET-001、US-RES-001、US-SYS-001 真实结果的展示；其他页面按 §1.4 与 UI style profile 保持一致。
> **覆盖边界（2026-09-01 规格审查）**：Phase 4 `4.0a` 只交付这些既有能力的生产展示接线、布局与交互连续性，不重新实现或重新宣称上述故事的检索质量、唤醒调度、反馈存储、任务队列或审计 AC。对应领域 AC 的权威仍是各故事与既有 Core 测试；`4.0a` 必须证明自己消费真实结果且不改变其 ID、排序和状态语义。Phase 3/3F 证据中仍为 Stub/partial 的 US-AWK-005 媒体/音乐、左右滑、感受持久化与审计由独立任务 `4.0d` 交付，禁止用 4.0a 的视觉卡片或 4.2 的测试任务冒充完成。

1. Home 是 `discovery` surface，内容顺序为 Ask Echo → 有真实匹配时的今日回响 → 最近导入 → 数据充足时的主题/时间集合 → 仅在活跃时出现的后台任务状态。
2. `visibleMemoryCount` 只统计当前 UserPolicy 下仍获授权、未排除、原始来源可解析且可安全展示的真实记忆。0 条记忆显示诚实空态：仅在 ProgressActor 存在真实活跃扫描任务时显示其确定进度；扫描已完成或没有扫描任务时显示授权/分享导入引导，不显示 ProgressView 或“正在扫描”文案。1~19 条显示 Ask Echo、真实可执行建议与最近导入；20 条及以上进入 rich-data 状态。任何状态均禁止 fixture、Preview、伪造记忆、伪造结果或假进度补位；允许使用本地化建议文案，但每条建议必须携带可直接提交给现有 SearchPipeline 的查询/筛选 payload，并通过当前能力检查。
3. rich-data 状态在非 Accessibility Dynamic Type、VoiceOver 关闭、可用内容宽度至少 340pt（2 × 164pt 最小卡宽 + 12pt 列距）且单个区块至少有 6 张真实可展示卡片时，默认使用双列 adaptive masonry；任一条件未满足时回退单列。
4. Search 是 `discovery` surface。UI 薄适配器必须为每个结果映射确定性的 `presentationKind = scanEligible | continuousReading`：照片/视频且来源可解析，或已有可独立理解的短摘要，映射为 `scanEligible`；“短摘要”精确定义为去除首尾空白后非空且不超过 160 个 Swift `Character`（扩展字形簇）；超出 160 个字符、需要连续阅读的备忘录/语音转写或长正文映射为 `continuousReading`。仅当可展示结果不少于 6、`scanEligible` 严格多于半数、非 Accessibility Dynamic Type、VoiceOver 关闭且可用内容宽度至少 340pt 时默认使用 adaptive masonry；平票按单列处理。布局必须保持 SearchPipeline 的相关度语义顺序、partial/low-confidence 状态以及反馈 `memoryId` 绑定。
5. “可展示卡片/结果”指稳定 `memoryId`、来源身份与 Focus 跳转均可解析，并且媒体卡具有真实 aspect ratio 或文本卡具有真实摘要的项目；原始来源已删除、权限已撤回或无法安全解析的项目不得计入布局阈值。卡片高度只来自真实媒体 aspect ratio 或文本摘要长度，不使用随机高度；时间/地点 metadata 仅在真实存在时展示，不得补造。
6. Accessibility Dynamic Type、宽度不足、关键内容无法安全裁切或辅助技术无法理解跨列顺序时，必须回退单列；VoiceOver 顺序始终按语义数据顺序。
7. App Shell、导航、Tab Bar、搜索行为、Focus 和 Task surfaces 保持 Apple 原生；禁止复制 Pinterest 的品牌、颜色、控件、文案或可识别 trade dress。
8. 通用 Discovery 记忆卡在 masonry/ScrollView 中不定义水平滑动手势，移除、收藏、反馈等动作使用显式按钮、菜单或 `accessibilityAction`，避免与纵向滚动和辅助技术冲突。US-AWK-005 专用交互式唤醒卡由 `4.0d` 交付，保留 AC-2 的左滑“下一张”/右滑“记录感受”语义，并必须提供等价的可见按钮与辅助功能动作；该例外不得扩散为所有记忆卡的通用手势。

### US-AWK-001：基于地理围栏的情境记忆唤醒（仅离开重置，永不重复推送）

> 🔧 **AC 修订（Phase 4 / ADR-018，2026-09-04）**：后台区域唤醒采用分阶段定位授权。首次启用只请求 When In Use；若用户要求 App 被终止后仍继续区域唤醒，必须先解释能力差异，再由第二个明确动作请求 Always。通知授权是独立投递 opt-in，不与定位请求串联。

> 📌 **实现状态（3F.8，2026-08-11）**：`CoreLocationProvider` 接入生产（CLLocationManager 地理围栏 enter/exit 事件 → AwakeningPipeline），权限感知（denied 静默禁用）；卡片持久化 + 本地通知投递；`.contextualAwakening` 审计。ADR-012 管辖。

- **优先级**：P1

- **用户故事**：当我走进大学附近时，Echo 主动推送相关记忆；同一围栏的推送间隔基于离开并再次进入重置，若从未离开则永不重复推送。

- 验收标准

  ：

  1. 触发条件仅为单一地理围栏**进入事件**（收到 `CLRegion.didEnter` 回调）。
  2. 同一围栏的推送重置规则：
     - 当用户收到 `CLRegion.didExit` 回调时，视为离开。再次收到 `didEnter` 时，重置计时，可触发新推送。（不额外要求持续离开时间）
     - **若用户一直停留在围栏内（从未离开），则永不重复推送同一围栏的记忆**（即推送一次后不再推送，直到用户离开后重新进入）。
  3. 推送内容与该地理位置关联的记忆匹配度 ≥0.7。
  4. 生成交互式回忆卡片（US-AWK-005）。
  5. 用户明确启用地理围栏时，若定位状态为 notDetermined，仅请求 When In Use 并等待系统回调后更新状态；不得同时请求通知。若用户需要 App 被终止后仍继续区域唤醒，先解释 When In Use 与 Always 的能力差异，再由第二个明确动作请求 Always。denied/restricted 时静默禁用并提供用户发起的系统设置恢复；重新开启定位后，若用户已在围栏内，不会立即触发推送，等待下一次进入事件。
  6. 审计记录 `.contextualAwakening`，含 `triggerType=geofenceOnly`、`memoryIds`、`resetByExit`。

### US-AWK-003：情绪感知记忆唤醒（缓存有效期24小时，防抖）

> 🔧 **AC 修订（Phase 4 / ADR-018，2026-09-04）**：HealthKit 读取授权结果受系统隐私保护，App 不得把 `authorizationStatus(for:)`（写入授权）或授权请求 completion 的 success 布尔解释为 HRV 读取已授权。UI 只表达 request lifecycle 与实际数据可用性。

> 📌 **实现状态（3F.8，2026-08-11；4.0f 修订，2026-09-04）**：`HealthKitSystemProvider` 接入生产——HRV 情绪推断（US-AWK-003 AC-1）且符合 3F.6 `CrossAppSourceProvider`（sourceType="health"）供 US-SRC-010 fusion；4.0f 改为 request lifecycle + 实际样本可用性，不再以写入授权状态推断读取权限；数据最小化（仅最小化时序样本）。ADR-018 管辖读取授权语义。

- **优先级**：P1

- **用户故事**：当系统检测到我处于负面情绪时，Echo 主动推送往日快乐高光时刻；如果 HealthKit 无数据，则通过我近期的查询和记录感受进行情感分析来触发。

- 验收标准

  ：

  1. 用户明确启用健康上下文后，仅请求读取 HRV 所需的最小 HealthKit 类型。授权请求成功处理后记录 app-level `requestCompleted`，不得显示 HealthKit read `granted/denied`；请求处理失败时不写 `requestCompleted`、显示 L2 可重试错误。仅当查询实际返回可读 HRV 样本时使用 HealthKit 推断情绪状态；设置页查询失败显示 L2，唤醒运行时查询失败按本轮无可用健康样本进入 AC-2 本地回退。设备不支持 HealthKit 时显示 `unsupported`，不发起请求。
  2. 若用户未请求健康上下文、HealthKit 查询无可读样本或设备不支持 HealthKit，则分析用户最近 **7 天**内的**查询字符串**和**记录的感受（US-AWK-005）**，使用本地情感分类模型（positive/negative/neutral）。该窗口固定为 7 天，不可配置。每天分析一次并缓存结果，**缓存有效期为 24 小时**。同时，用户每次新增查询或感受时，可触发异步更新缓存，**但需使用防抖机制**：在已有异步分析任务未完成时，不启动新的分析；或者采用延迟执行（如最后一次触发后延迟 30 秒再执行），避免频繁计算。
  3. 负面情绪（negative）→ 检索 positiveEmotion 标签记忆；中性（neutral）或平静状态 → 检索 reflective/introspective 标签记忆；积极情绪（positive）→ 不触发额外推送（避免过度打扰）。
  4. 生成交互式回忆卡片，文案温和不评判。
  5. 审计记录 `.emotionalAwakening`，含 `detectedMood`、`source=healthKit|textSentiment`、`cachedResultUsed`。

### US-AWK-005：交互式回忆卡片（感受内部可用，音乐推荐使用离线库）

> 📌 **实现状态（3F.8，2026-08-11）**：`LocalNotificationAdapter`（通知请求/调度，内容最小化）+ `NotificationResponseRouter`（点击→详情路由）接入生产；`AwakeningCardRepositoryActor` 持久化卡片（重启去重）；通知内容仅含 memoryId + triggerType（不含原文）。ADR-012 决策-3/5/7 管辖。

> 📌 **4.0d 规格合理性复审（2026-09-02）**：Apple Music catalog/personal recommendation 属于网络 Web Service，与 Echo 运行时零上传/零下载红线冲突；任务改为“随包离线库默认推荐 + 用户显式选择后可读取设备上已下载的媒体库”，禁止 MusicKit catalog/personal/recently-played 网络请求。`userFeelings` 是逻辑集合，物理存储为以 `memoryId` 为外键的独立关系表，不是 canonical memory JSON 列。详见 ADR-016。

- **优先级**：P0

- **用户故事**：推送内容包含文案+照片+背景音乐建议，支持“下一张”、“记录此刻感受”，点击可跳转原始数据。

- 验收标准

  ：

  1. 卡片展示本地生成文案；当关联记忆确实包含可解析媒体时展示 1~3 张真实照片/视频缩略图，不得为无媒体记忆伪造缩略图。音乐建议默认由随 App 打包的离线曲库产生：manifest 声明受支持年份，每个受支持年份 20 条元数据，并提供无年份匹配时的通用 fallback 分组；选择由 memoryId digest 稳定决定。Bundle 仅包含曲名、艺人、发行年份、内部分组/标签与来源/授权声明，禁止打包音频、封面、歌词或网络 URL，随 App 版本更新且不要求 Apple Music 授权。仅当用户在卡片中显式选择“匹配此设备音乐”后，才可请求媒体库权限并通过 `MPMediaQuery` 读取设备上已下载（`isCloudItem == false`）的曲目元数据；拒绝、受限、库为空或查询失败均静默回退到随包离线曲库。禁止 `MusicCatalog*`、personal recommendations、recently played 或任意 MusicKit Web Service 请求，禁止上传记忆、查询、感受或派生标签。离线曲库条目仅是建议，不伪造可播放状态；设备曲目只有在本地可播放时才显示播放动作。
  2. 专用唤醒卡支持左滑“下一张”、右滑“记录感受”（弹出本地文本框），并同时提供产生相同 ViewModel intent 的可见按钮与 `accessibilityAction`。“下一张”按当前唤醒结果的稳定顺序前进，不改变 Search/Awakening 排序真相；无下一项时禁用该动作。打开感受编辑器不等于已记录，只有成功提交才产生 `record` 审计。
  3. 卡片中的媒体/文案/语音动作通过稳定 `memoryId` 与当前授权下可解析的 `sourceLocator` 进入 Echo 已有的类型化 Focus surface：PhotoKit 照片/视频 → 当前授权范围内的媒体详情；Share Extension 文本 → Echo 已保存的 canonical 文本阅读；Share Extension 音频因 US-ING-003 不持久化原始音频，v1 只进入转写文本阅读，不显示原始语音播放。来源失效、撤权、limited 范围隐藏或内容离线不可用时显示对应的诚实状态，不回退到 fixture/bundled sample，也不得猜测分享来源 App。`4.0d` 负责 card → Focus 的 intent；`4.0h` 负责类型化来源解析与具备能力时的 PhotoKit 原始删除；`4.0i` 负责经复验的 source anchor 与稳定 Detail 路由。
  4. **“记录感受”内容不作为独立的新记忆摄入**。领域层将其暴露为原记忆的 `userFeelings: [UserFeeling]` 扩展集合；物理层使用独立 `MemoryFeeling` 关系表，每行至少包含 `feelingId`、`memoryId`、`text`、`createdAt`、`updatedAt`，以 `memoryId` 关联 canonical memory。感受不创建 Memory/Representation，不写入 FTS/向量/翻译缓存，不支持用户搜索；仅可被本地个性化/情绪分析读取。新增、编辑、删除均须事务化，支持重启恢复；原记忆删除时同事务级联删除其感受，且不写入 `ExcludedAssets`。用户可在同卡片或记忆详情中查看、编辑、删除历史感受；删除对个性化的影响在下一次定时任务（每日凌晨）或用户手动重置 Prompt 时体现（参考 US-SYN-005）。
  5. 已执行的交互记录 `.cardInteraction`：`action` 仅为 `next/record/jump`；`cardIdDigest`、`memoryIdDigest` 使用 hash-only 摘要；`feelingAssociatedToSource` 为布尔值，仅成功保存且仍关联原 `memoryId` 的 `record` 为 `true`，其他动作为 `false`。审计禁止感受原文、媒体库内容和未哈希标识符；取消感受编辑器不记 `record`。

### US-AWK-007：手动编辑记忆卡片（允许补充描述）

> 🔧 **AC 修订（Phase 4 / ADR-017，2026-09-03）**：v1 描述编辑采用多行纯文本，不承诺富文本格式持久化。用户编辑作为 canonical memory 的 `MemoryUserEdit` 关系扩展保存，原始来源内容保持不变；冲突使用持久关系而非仅内存 UI 状态。

- **优先级**：P1

- **用户故事**：作为用户，我希望在回忆卡片上直接编辑记忆的标题、描述、自定义标签，甚至覆盖时间戳，让记忆更符合我的主观感受。修改后重新向量化，旧元数据删除。

- 验收标准

  ：

  1. 记忆详情页提供“编辑”入口，允许修改：可选标题、多行纯文本描述、自定义标签列表、覆盖时间戳（用户可自定义日期时间）。用户可以为原本无文本的图片/视频添加描述文字。原始来源文本不被覆盖；用户编辑持久化到以 `memoryId` 为外键的 `MemoryUserEdit` 关系并随记忆级联删除。
  2. 保存时基于固定顺序的有效文本（用户标题、用户描述、规范化标签、原 canonical 文本）生成新表示与向量。发布事务必须原子写入新的 `MemoryUserEdit`/FTS/representation 绑定、结构化审计和待处理旧向量清理；发布提交前任一步失败保留旧可服务版本。发布提交后保存视为成功，旧向量清理或索引持久化失败不得把已提交保存报告为失败，而应保留旧向量并将清理留在 `PendingOperations`，仅由用户手动重试，成功后删除待处理记录。更新 `userEdited=true`。首次覆盖时间戳时将原值写入 `originalTimestamp`，后续覆盖不得改写该备份。
  3. 若编辑时该记忆正被后台同步任务更新，则**阻止保存**，并显示提示：“该记忆正在同步更新中，请稍后再编辑”（引用统一错误矩阵 L4）。
  4. 若记忆存在未保存的编辑会话或已持久化的用户编辑，而外部数据源发生变更，系统不应自动覆盖，也不得允许普通保存绕过冲突解决；应将外部版本摘要、检测时间和可重放的来源变更参数持久化到 `MemoryEditConflict`，并在当前或下次打开编辑时显示“**内容冲突**：外部数据源已被修改。请选择：保留您的编辑 / 使用外部新版本 / 查看差异并合并”。需提供差异对比 UI。选择“保留您的编辑”时，在同一 SQLite 事务内清除 conflict 并写 `userLocked=true`；完成手动合并时，编辑发布、清除 conflict 与写 `userLocked=true` 必须属于同一条件事务。选择外部版本时必须重放已持久化的来源变更，只有 canonical/representation 替换成功后才通过级联清除用户编辑与 conflict，并保持 `userLocked=false`；重放失败时保留 conflict 供重试。后续自动同步跳过 `userLocked=true` 的记忆，直到用户显式“重新同步”或恢复外部版本。
  5. 编辑后的人工记忆仍关联原始数据源（如有），但检索时可优先展示人工编辑版本。
  6. 当用户覆盖时间戳后，检索时使用**覆盖后的时间戳**作为主索引。原始拍摄/创建时间戳保存为 `originalTimestamp` 字段，仅在详情页展示，不参与时间范围检索。
  7. 审计记录 `.memoryEdited`，含结构化 `editedFields`、`reindexed`、`conflictResolvedWith`；记忆 ID 与自由文本只记录摘要，不记录标题、描述、标签或外部版本原文。

## 7. 隐私与数据主权模块（8 Stories）

### US-PRV-001：动态授权即时生效（重新授权后提供一键恢复排除项，仅限当前数据源）

- **优先级**：P0

- **用户故事**：当我关闭某类数据授权后，后续检索立即排除该类数据；当我重新开启授权后，系统应允许我重新导入该类数据，并提供一键恢复之前排除的项目的选项（仅限该数据源）。

- 验收标准

  ：

  1. UserPolicy 更新后，**下一次检索调用前**生效。
  2. 被拒数据不进入 Retriever。
  3. 仅依赖被拒数据时返回 Denial Response。
  4. 相关缓存自动失效。
  5. 当用户将某个数据源从“拒绝”改为“授权”时，系统**不自动清除 `ExcludedAssets` 表中的相关条目**，但在设置页或弹窗显示提示：“检测到您重新授权了 [数据源名称]，之前排除的项目仍保持排除。是否一键恢复所有排除项？（仅限当前数据源）” 提供“一键恢复”和“稍后手动处理”两个按钮。若用户选择一键恢复，则将该数据源对应的所有 `ExcludedAssets` 记录移除并触发重新导入。
  6. 审计记录 `decision=.denied`、`policyVersion`；重新授权时记录 `.reauthorized`，含 `sourceType`、`excludedBatchRestored`。
  7. `PrivacyOperation.search` 是操作类型，不是用户数据源；`UserPolicy.authorizedSourceTypes` 只保存可由用户授权或撤销的真实来源（如 photo/note/voice/video/thirdParty），不得要求历史策略包含伪来源 `search`。检索入口仍必须执行 `.search` PrivacyCheckpoint，随后按真实结果来源逐项过滤；旧策略缺少 `search` 时不得因此拒绝整个检索，也不得借兼容修复恢复任何已撤销的真实来源。

### US-PRV-002：审计日志查看

- **优先级**：P1

- **用户故事**：作为用户，我希望在 App 内查看最近 30 天的隐私操作记录。

- 验收标准

  ：

  1. 按时间倒序展示，含操作类型、决策结果。
  2. 详情含 Trace ID、哈希、策略版本、耗时。
  3. 无任何原始用户数据。
  4. 超 30 天记录不可见。
  5. 列表加载 P95 <500ms。

### US-PRV-003：审计日志导出

> 🔧 **AC 修订（Phase 3F / ADR-006，2026-08-04）**：审计日志导出修订为**有界分页/分片**——30 天审计日志按页/分片导出，避免单文件无界增长；替换原『完整导出且 ≤5MB 且无分页规则』的不可落地 AC。

- **优先级**：P1

- **用户故事**：作为用户，我希望导出审计日志用于个人存档或合规审查。

- 验收标准

  ：

  1. JSON 格式，结构与 App 内展示一致。
  2. 导出文件 NSFileProtectionComplete 加密。
  3. 导出过程不阻塞 UI。
  4. 审计记录 `.auditExported`。
  5. 导出文件大小 ≤5MB。

### US-PRV-004：记忆删除时的原始文件处置确认

> 🔧 **AC 修订（Phase 4 / ADR-019，2026-09-05）**：Echo 只能发起删除当前授权范围内可获取、通过 `PHAsset.canPerform(.delete)` 的 PhotoKit photo/video。Share Extension 导入内容不具备来源 App 删除权限。PhotoKit 与 Echo 存储不能组成单一事务；同一删除日志必须把外部系统结果与本地 D-005 phase 正交保存，未经确认不得推进本地清理。

- **优先级**：P0

- **用户故事**：用户删除某条记忆时，系统必须询问是否同时删除原始媒体文件，并根据选择正确处理数据授权状态。

- 验收标准

  ：

  1. 删除操作触发确认。所有记忆提供“仅从 Echo 移除”；仅对当前 UserPolicy 允许、PhotoKit `.readWrite` 状态为 authorized 或 limited、资产在当前范围内可获取且 `PHAsset.canPerform(.delete)==true` 的 photo/video 提供“同时删除原始文件”。Share Extension 导入内容及只读、失效、limited-hidden 来源不显示可执行的原始删除选项，并明确 Echo 无法删除来源 App 中的原件。App 内选择后，`PHPhotoLibrary.performChanges` 仍由系统呈现编辑确认。
  2. 选择“仅从 Echo 移除”时，将该 Asset ID 写入本地 `ExcludedAssets` 表，且事务性清除该记忆的所有副本（向量、索引、缓存、元数据）。
  3. 选择“同时删除原始文件”时，先验证来源、UserPolicy、PhotoKit 授权与 `canPerform(.delete)`，再持久化同一 `MemoryDeletionJournal` 的 `intentKind=photoLibraryAndEcho`、`phase=.planned`、`sourceDeletionState=.prepared`。系统 completion 成功后必须先持久化 `sourceDeletionState=.confirmedDeleted`，才允许从 `.planned` 进入既有 D-005 本地清理，且**不写入 `ExcludedAssets`**。用户取消、系统拒绝或删除失败时记录 `notDeleted`，保持 canonical、向量、缓存和 ExcludedAssets 全部不变并安全结束 intent。崩溃恢复时：full authorized 下资产仍存在则结束为未删除；full authorized 下确认不存在才可记为 `reconciledAbsent` 并推进；limited 下不可获取或权限 denied/restricted/notDetermined 均为 `indeterminate`，必须保留 Echo 数据与 journal、显示 L2 恢复动作，禁止把“不可见”推断为“已删除”。系统已确认删除后若 Echo 清理失败，保留日志并进入 L2 手动重试/下次前台补偿；不得声称可以回滚系统资产。
  4. `ExcludedAssets` 表中的条目不会被任何自动导入或定时检测流程重新导入，但用户可以通过“已排除项目”管理界面（US-SRC-008）手动恢复。
  5. 对应审计日志条目标记 `.memoryDeleted`，结构化包含 `preservedOriginal`、`sourceDeletionRequested`、`sourceDeletionCompleted`、`sourceDeletionOutcome`、`excludedWritten`、`success`；ID 仅记录摘要。用户取消、系统拒绝、失败或 `indeterminate` 必须保持 canonical 数据未变，并记录真实结果而非删除成功。

### US-PRV-005：全部数据删除与账户注销（冷却期内每3小时提醒）

> 🔧 **AC 修订（Phase 3F / ADR-006，2026-08-04）**：冷却期提醒与完成**无法在 App 未运行状态下保证**（iOS 挂起限制）——改为 App 下次启动/前台时补偿提醒；3 小时冷却期提醒以 best-effort 本地通知投递。

- **优先级**：P0

- **用户故事**：作为用户，我希望彻底删除 Echo 中的所有索引、向量、设置，但保留系统相册中的原始文件。

- 验收标准

  ：

  1. 二次确认 + 冷却期 24h。
  2. 用户发起注销后，立即显示明确提示：“**冷却期 24 小时内新增或修改的数据将在注销后永久删除。**” 并且在冷却期内每次启动 App 时都提示剩余时间和后果。**此外，在冷却期内，若 App 处于前台状态，每 3 小时显示一次非侵入式提醒**：“您仍在注销冷却期中，剩余 X 小时，数据将在冷却期结束后被删除。”
  3. 冷却期内，Echo 数据仍正常可见，用户可正常使用所有功能（检索、编辑、新增等）。所有新产生的数据继续正常存储。
  4. 冷却期内用户可以撤销注销，撤销后所有数据原样保留（不丢失冷却期内新增的数据）。
  5. 冷却期结束后，异步擦除所有 Echo 数据（包括冷却期内新增的数据）。擦除完成后，App 进入首次启动状态，需重新授权数据源。
  6. **不删除**系统相册/备忘录/健康等原始数据。
  7. 擦除完成后审计数据库自身擦除。

### US-PRV-006：所有记忆永久保留（永不自动过期）

- **优先级**：P0

- **用户故事**：作为用户，我希望所有类型的记忆（媒体、文本、AI 创作等）均不设自动过期/删除机制，仅通过手动删除或原始文件级联清除移除。

- 验收标准

  ：

  1. 系统中不存在任何 TTL、保留周期或自动清理定时任务。
  2. 设置页中无“记忆保留周期”相关选项。
  3. 媒体类型记忆（image/video/audio）不受任何保留策略影响。
  4. 文本类型记忆（note/transcript）同样永不自动过期。
  5. 记忆仅可通过用户手动删除（US-PRV-004）或原始文件删除级联清除（US-PRV-007）两种路径移除。
  6. 审计记录 `.retentionPolicyEvaluated`，含 `mediaExempt=true`、`textExempt=true`、`autoExpiry=false`。

### US-PRV-007：原始媒体文件删除级联清除（同时清理 ExcludedAssets 无效记录，并提示用户）

> 🔧 **AC 修订（Phase 4 / ADR-019，2026-09-05）**：v1 只对可通过 PhotoKit localIdentifier 可靠观察的 photo/video 提供自动级联。Share Extension 原件位于其他 App/文件提供者控制域，Echo 不声称能监听其删除。limited-hidden 或撤权导致的不可见不是删除证据；硬性“5 秒内完成”改为收到可验证删除事件或 full 授权下确认缺失后尽快启动可恢复清理。

- **优先级**：P0

- **用户故事**：当 Echo 可可靠确认用户已在系统相册删除关联的原始 photo/video 时，自动清除对应数据副本，并清理 `ExcludedAssets` 中的无效记录，同时在用户实际进入管理界面后提示用户。

- 验收标准

  ：

  1. 监听 `PHPhotoLibraryChangeObserver`，并在 App 启动/进入前台时补偿核对已追踪的 PhotoKit localIdentifier。Share Extension text/audio/file 不承诺通用文件系统删除监听。
  2. 只有收到可验证 PhotoKit 删除事件，或在 full `.authorized` 范围下确认 localIdentifier 不存在时，才启动对应记忆的向量、索引、缓存、元数据可恢复清理。`.limited` 下不可获取、权限撤回或受限均不得视为删除。清理过程**不向 `ExcludedAssets` 写入任何记录**，但若存在该 Asset ID 的排除记录则自动删除。若清理了排除记录，持久化一次性待提示状态；用户后续实际打开“已排除项目”管理界面时显示：“部分已排除的原始文件已被删除，已自动从排除列表中移除。”
  3. 清除失败时记录本地错误日志并保留可重放 journal；L1 可在当前执行机会内按统一退避策略重试，仍失败升级 L2，只能由用户手动重试或下次前台补偿，不得无限自动重放。
  4. 级联清除过程不阻塞主线程，不影响 App 正常交互。
  5. 审计记录 `.cascadeDeleteFromOriginal`，asset/memory identity 仅保存 hash digest，并包含 `success`、`excludedWritten=false`、`excludedAutoCleaned`。清理发生时先记录 `userNotified=false`；只有一次性提示实际展示后，才另写 `.excludedAutoCleaned` 展示事件并记录 `userNotified=true`。

- **用户故事**：作为中国用户，我希望在首次使用时清晰了解数据处理方式，并可随时撤回同意。

  3. 同意按钮与拒绝按钮同等醒目，二者在同一可见层级中呈现；不得预选同意、弱化拒绝、以滚动终点隐藏拒绝或使用颜色/尺寸诱导同意。

  1. App 前台时，在顶部状态栏或设置页实时显示活跃任务列表（如“正在同步新照片 32/128”、“正在构建向量索引”）。
  2. 每个任务显示进度百分比或计数。
  3. 支持对单个任务执行“暂停”或“取消”操作：
     - **暂停**：任务保持同一个 in-memory job 和已持久化 checkpoint，在协作式安全点挂起，不得把“抛错并丢弃 job”冒充暂停；App 进程结束后则转为可重建的未完成记录。
     - **取消**：正在执行的任务必须先协作式终止并持久化最后安全 checkpoint，才能向 UI 报告已取消。下次用户恢复该精确 `taskId` 时，弹窗询问“检测到未完成的进度，是否继续？”，用户可选择“继续”或“重新开始”。尚未开始且 checkpoint 为 0 的排队任务可直接移除，不生成无意义的 0/N 恢复提示。
  4. 断点续传的进度存储在本地 SQLite 数据库（表 `TaskProgress`）中，采用事务写入。`resumeData` 必须是有版本、有大小上限、可校验的 Sendable 值类型描述，不得包含可执行闭包、Actor 实例、授权快照或记忆原文。Continue 按精确 `taskId` 保留并消费现有 checkpoint，入队时不得先覆盖为 0。Restart 先验证 launcher 和当前隐私/数据源授权，再在单个 SQLite 事务中将同一 `taskId` 的 checkpoint 替换为 index 0 的可重试记录，之后单独入队；入队失败时保留该 index 0 记录并显示 L2，不得声称 restarted。任务实际入队后成功或不可继续的最终执行失败时立即删除 `TaskProgress`；重建/入队前的 L2、未知/过期类型或取消/暂停必须保留记录。
  5. 无活跃任务时，状态面板自动隐藏。
  6. 任务队列策略：索引构建与数据同步串行执行，避免资源争抢。
  7. 审计记录 `.backgroundTaskUIAccessed`、`.backgroundTaskInterrupted`（含 action=pause/cancel, resumePoint, userChoiceOnRestart, outcome；只有操作真实成功后才能记录成功 outcome）。

### US-FBK-002：本地反馈驱动重排（阈值 0.80，时间衰减，单条记忆权重上限 ±0.5 截断，支持重置/撤销）

> 📌 **实现状态（3F.6，2026-08-11）**：重排公式已实现并通过测试（阈值 ≥0.80 / 时间衰减 1.0-0.5-归档 / 截断 ±0.5 / `finalScore = cosineSim + adjustment`）；3F.6 新增 query-conditioned 过滤（`computeAdjustment` 按 `queryText` 精确匹配）+ `FeedbackPipeline` 传递活跃 generationId（ADR-010 决策 4）。

- **优先级**：P2

- **用户故事**：Retriever 利用本地反馈数据动态调整检索结果排序，采用固定余弦相似度阈值（0.80）与时间衰减策略，避免旧偏好永久影响；单条记忆的反馈累积权重设有上限；用户可重置所有反馈或撤销单条反馈。

- 验收标准

  ：

  1. 反馈匹配策略：检索时，对比查询向量与记忆向量的余弦相似度，**仅当相似度 ≥ 0.80** 时才应用反馈权重，低于此阈值的反馈不参与重排。
  2. 时间衰减：每条反馈记录独立计算衰减系数，根据该条反馈的年龄（从记录创建时间到当前检索时间的天数）：
     - 年龄 ≤ 90 天：衰减系数 = 1.0
     - 90 天 < 年龄 ≤ 180 天：衰减系数 = 0.5
     - 年龄 > 180 天：自动归档，不参与重排（相当于忽略）。
  3. 重排公式：先计算原始调整值 `rawAdjustment = Σ(点赞权重_i * decayFactor_i) - Σ(点踩权重_j * decayFactor_j)`，然后截断至 [-0.5, 0.5] 范围：`adjustment = max(-0.5, min(0.5, rawAdjustment))`，最终 `finalScore = cosineSim + adjustment`。
  4. 反馈数据存储在本地 SQLite 数据库（`FeedbackStore`），**永不上传**。
  5. 设置页提供“清除所有反馈学习数据”按钮，点击后清空 `FeedbackStore` 中的反馈记录表（包括归档记录），所有重排权重恢复默认，需要二次确认。
  6. 在“我的反馈记录”页面（US-FBK-003），每条反馈（包括已归档但不参与重排的记录）旁提供“撤销”按钮，点击后从 `FeedbackStore` 中物理删除该条记录。删除后即时生效，下一次检索即反映变更。
  7. 审计记录 `.feedbackReceived`（含 `decayFactor`）、`.feedbackReset`、`.feedbackRevoked`。

## 13. 技术契约备忘（v4.6）

1. **ExcludedAssets 写入规则**：仅用户主动“仅从 Echo 移除”写入；系统自动删除旧记忆、原始文件级联删除均不写入，但级联删除会清理无效排除记录并提示用户。重新授权时提供一键恢复选项（仅限当前数据源）。
2. **重新授权行为**：提供一键恢复排除项选项（仅当前数据源）。
3. **反馈阈值**：余弦相似度 ≥0.80 才应用反馈，单条记忆权重调整上限 ±0.5（截断）。
4. **低电量开关**：独立控制是否暂停后台任务，默认开启。
5. **冲突解决 UI**：提供差异对比与合并选项；用户选择“保留编辑”后自动锁定该记忆，永久跳过自动同步。迁移冲突支持批量应用。
6. **感受存储**：领域 API 暴露 `userFeelings` 集合，物理存储为以 `memoryId` 为外键的 `MemoryFeeling` 关系表；不创建 Memory/Representation，不支持用户检索，但系统内部可用于本地分析。删除感受后，个性化分析在下一次定时任务或手动重置时体现。
7. **断点续传**：使用 SQLite 表 `TaskProgress` 存储进度，取消后再次启动时询问是否继续；任务完成后自动删除进度记录。
8. **统一错误响应矩阵**（见第 14 章），所有故事引用此矩阵处理重试与冲突。L2 仅支持手动重试，无自动重放。
9. **PendingOperations 表清理**：最大条目数 1000，超出时丢弃最旧记录并记录审计。无自动重放，仅用户手动重试。
10. **日历变更检测**：前台对比 `lastModified` 时间戳为主，通知仅辅助。
11. **模型加载失败**：无网络下载，仅提供手动重试按钮（重试本地已有模型）。移除 ODR。
12. **注销冷却期**：期内每 3 小时提醒一次，数据正常使用，撤销后完全恢复。
13. **已排除项目界面**：分页懒加载，首次 50 条，提供手动刷新按钮。
14. **备忘录哈希跳过阈值**：100KB 或可用内存 <300MB 或总内存 ≤2GB，仅在同步开始时判断一次。
15. **音乐推荐**：默认使用内置离线曲库（按年份分类，每年 20 条元数据），随 App 版本更新，不依赖网络。仅在用户显式启用后读取设备上非云端的媒体库元数据；禁止 MusicKit catalog/personal/recently-played 网络请求。
16. **相册 iCloud 提示**：增加跳转设置按钮，兜底文本。
17. **策略版本号**：`policyVersion` 为一个递增整数，每次用户通过设置页修改任何隐私相关选项（授权、排除、保留策略等）时递增。App 升级时保持原版本号（因为策略未变）。初始版本为 1。
18. **原子性清除**：不要求跨存储事务，允许使用两阶段提交或补偿回滚，最终保证一致性。

## 14. 统一错误响应矩阵（v4.6，仅支持手动重试）

| 错误等级          | 触发条件示例                                                 | 用户感知                                         | 系统行为                                                     | 审计记录                            |
| ----------------- | ------------------------------------------------------------ | ------------------------------------------------ | ------------------------------------------------------------ | ----------------------------------- |
| **L1 - 瞬态**     | PHPhotoLibrary 繁忙、本地媒体库查询失败、内部数据库锁、索引构建临时失败 | 无 Toast；后台静默重试                           | 指数退避重试（1s→2s→4s），最多 3 次；若 3 次后仍失败，**升级为 L2**，写入 `PendingOperations` 表；唤醒卡音乐建议可直接回退到随包离线库，不以网络重试 | `.retrySuccess` / `.retryEscalated` |
| **L2 - 可恢复**   | 备忘录保存失败、权限临时拒绝、磁盘空间不足、L1 升级后        | Toast + “重试”按钮                               | 写入 `PendingOperations` 表，**无自动重放**，仅用户点击重试按钮时执行。`PendingOperations` 表最大 1000 条，超出丢弃最旧记录 | `.retryPending`                     |
| **L3 - 阻断**     | 永久权限拒绝、API 废弃、数据库损坏、模型加载失败、`PendingOperations` 条目过多 | 全屏引导页 / 设置页红点 + 跳转系统设置           | 停止相关功能；不自动重试；引导用户修复                       | `.fatalError`                       |
| **L4 - 数据冲突** | 资产被外部删除、备忘录被用户手动修改、后台同步与手动编辑同时发生 | 非破坏性提示（Banner/Toast），提供“解决冲突”入口 | 保留本地副本/用户编辑内容；标记 `conflict`；不自动覆盖，提供手动合并界面；用户选择保留编辑后锁定 | `.syncConflict`                     |
