# ADR-024: 创作复制与导出默认只包含标题和正文

**状态**：已接受（依用户 2026-09-08 Live Review 反馈执行）
**日期**：2026-09-08
**决策人**：用户提出修复要求；Codex 实施

## 背景

用户反馈复制及 PDF 等导出内容仍包含 MemoryID。此前只修复了页面上的引用显示，`CreationExportService` 仍将内部 UUID 和 `NoSource` 等枚举标记逐段写入所有格式，PDF 还直接绘制 Markdown 控制符。旧的“所有格式保留引用”要求让内部 provenance 数据污染了用户要使用的创作文本。

## 决策

复制、plain-text 分享、Markdown、PDF、备忘录交接及打印准备默认只包含创作标题（如有）和正文。不附加 MemoryID、UUID、来源脚注或内部状态标记。诗歌段落之间使用单换行，其他模板保留空行分段，段落内部原文不改写。Markdown 保留标题与诗行的标准格式；PDF 使用可读文本，不绘制 Markdown 控制符。

App 内仍保留逐段 provenance、来源可用性/无来源提示及来源跳转。所有交接继续先通过 export coordinator 的当前 UserPolicy、PrivacyCheckpoint 和来源授权校验；授权检查消费完整领域对象，完成后才生成正文 payload。删除、报告依赖、语言校验与 hash-only 分享呈现审计均不改变。文本中用户/模型实际写出的字符不通过正则清理；本决策去除的是导出服务附加的元数据。

## 备选方案

- 保留原始 ID：不满足用户此次修复要求。
- 将 ID 改成来源编号：仍会在复制及导出时附加用户不需要的文字，本轮不采用。

## 后果

外部正文不携带 Echo 来源映射，来源核查在 App 内完成。覆盖旧测试中的标记存在断言，新增文本、诗行、实际 PDF 文字提取与分页完整性回归；授权失败仍必须阻止正文交接。

## 参考

US-SYN-002 AC-5、US-SYN-003 AC-3/4、ADR-013、ADR-020。本决策覆盖其中“所有格式必须保留引用”的外部表现要求，不削弱内部来源验证与隐私边界。
