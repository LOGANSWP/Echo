# ADR-025: 照片自动理解与无需手写描述的创作输入

**状态**：已接受（产品流程与任务拆分；具体视觉生成模型/运行时未选定、未审批）
**日期**：2026-09-08
**决策人**：用户要求修订相关文档和任务；Codex 同步

## 背景

照片生产摄入创建 `canonicalText=nil` 的 Memory，视觉向量用于检索。已有 OCR 路径将可见文字嵌入搜索表示，但没有将识别正文接入创作输入。4.0k 的生成运行时接收文本，手动创作只读取 canonical 文本和已保存的用户编辑。因此，普通无文字照片必须先由用户填写描述才能创作。此前双模拟器的蓝圆流程经过手动描述，不能证明照片直接创作。

规格中的“用户可以……补充文字描述”应为可选增强，不能成为照片创作的普遍前置条件。缺失的是图像到可用创作素材的功能链路，与已暂缓的诗歌文采优化不同。

## 决策

### 1. 任务边界

- `4.0k` 继续负责获批文本生成运行时、文本来源创作与有界分层报告。PR #79 为 Draft review；既有质量、设备、覆盖率门禁不迁走、不降级。
- 新增 `4.0l`：照片自动理解、机器描述/OCR 正文持久化、无需手写描述的手动创作与报告输入接线。依赖 `4.0k`，初始 `backlog`；相关发布验证、RC 和 Phase 4 集成门禁必须依赖它。
- 不回写已完成历史任务的验收结论。US-ING-004 新 AC-6~9、US-SYN-003 新 AC-7 与 US-SYN-004 照片输入补充在 4.0l 完成前均为未交付。
- 本决定只授权文档与任务规划，不批准新模型下载、权重替换、视觉模型工件、签名或发布。选型时复用 ADR-009/023 的确切工件、许可、预算审批流程；当前文本 LLM 批准不能当成视觉理解模型批准。

### 2. 用户流程

新照片经现有授权和生产摄入成功后，自动排入有界的本地图片理解任务；不阻塞照片本身导入、浏览和检索。自动生成基于真实像素的画面描述，含文字照片另提取 OCR 正文。无文字照片仍须通过画面理解获得素材，不能只完成 OCR 就宣称本任务完成。

准备完成后，用户直接选照片、选模板、生成；手写描述保持可选。准备中显示实际进度并允许在同一流程等待/继续，禁止用“请先填写描述”替代正常流程。失败、暂不可用、撤权分别按真实原因反馈；L2 仅手动重试，系统资源延后可在下一合法机会继续。用户可自愿补充文字，但不能被迫补写。无法可靠识别的照片允许明确不可用，不能以文件名、占位摘要或固定句子伪造成功。

已有照片通过版本化、有界、幂等补处理进入同一任务；重复导入、重复进入创作、前后台并发不得重复推理或覆盖用户编辑。不要求精确后台完成时刻。

### 3. 来源与持久化契约

图片的机器描述、OCR 原文与用户描述分开保存，关联原始稳定 MemoryID；由 DatabaseManager 管辖的 Actor 维护派生记录，绝不覆盖 `Memory.canonicalText`、`originalText` 或 `MemoryUserEdit`。每条派生结果至少记录内容种类、来源版本/内容身份、模型/预处理/提示版本、语言、状态和正文版本；数据库迁移及具体 schema 在 4.0l 实现时按该合同交付。

UI 显示“AI 生成的画面描述”和“OCR 识别文字”，保留用户校正入口。创作读取带来源类型的结构化素材：用户描述优先；用户明确校正不得被机器描述覆盖或在 Prompt 中重新引入冲突旧描述。没有用户描述时使用当前有效的机器描述，并可结合 OCR。用户只填写标题/标签时不应屏蔽机器画面描述。来源图片中的文字一律视为资料，不具指令权限。

画面描述只报告可见内容；不能从图像推断人物身份、关系、心理感受或画外事件。图像检索向量和 OCR 不等于视觉描述；机器描述也不等于已验证事实。所有创作锚点仍指向原照片 MemoryID，保留派生来源类型与版本供校验，不把机器文本伪装成用户原文或另建用户记忆。

### 4. 隐私、生命周期与预算

所有推理在本地完成，生产工件随 App 分发。入队、图像读取、每次模型调用、持久化及创作/报告 publication 前重新核验当前授权、来源及派生版本。队列支持取消、资源延后和合法恢复；限额覆盖图像尺寸/数量、OCR/描述文本长度、输入/输出 token、调用数、时间与驻留内存，具体值随工件材料冻结，不在本文猜测。

图片变更使旧描述/OCR 失效，重新排队；模型/预处理变更不能静默复用不兼容结果。用户排除、来源确认删除、全部撤权按既有 D-005 清除派生文本、表示/缓存、任务描述及受影响报告。撤权或照片不可读取时不得发布旧的在途结果；不可见不推断为已删除。恢复 checkpoint 不保存图片原件、OCR/描述原文或授权快照。审计只记录内容/身份摘要与允许的结构化状态，不记录正文、图片或 source locator。

### 5. 报告接线

4.0l 让当前已准备好且获授权的机器描述/OCR 参与月/年报告的有界来源选择，并沿用原照片时间戳、MemoryID、周期边界和全贡献输入删除关系。图片只导入而描述未准备好不等于没有记忆：只有当前授权范围确实无记忆时才是 `noData`。有其他可用来源时可生成部分报告并明确记录未准备/失败照片的 coverage；全部照片尚在处理时保留可延后状态，L2 失败仍仅手动重试，不能发布空报告或永久写入 `noData`。模型尚不可用时诚实返回能力不可用。

后续描述就绪不自动重写已完成报告，不移动 eligibleFrom，不重开 `invalidated` 周期，不自动补算关闭期间/基线之前历史报告。已有照片补处理仅准备素材；报告仍遵守 ADR-021 的周期与重新生成规则。

### 6. 验收与证据

- 双模拟器通过真实 PhotoKit 摄入无 PII 的普通无字图片，**不调用编辑、不手写描述、不直接写数据库、不注入 caption fixture**，完成自动描述 → 诗歌/其他模板 → 原照片来源跳转 → 复制/PDF/分享。
- 单独覆盖含字截图 OCR 与无字场景理解；描述是实际模型输出且对应所选图片。仅验证非空、模板成功或 OCR 命中不算通过。
- 新旧照片、有/无用户校正、中英文、批量限额、重复入队、应用重启、取消/恢复、来源编辑、撤权/删除、模型缺失/损坏、无有效描述、资源延后和报告部分/全部未准备矩阵必须有证据。
- 运行时与视觉模型单独提供 hash/许可/审批材料；先验证模拟器功能，最终设备资源/隐私/覆盖率门禁仍保留，不能以模拟器代替实机资格。

## 备选方案

- 强制手写：与用户期望不符，拒绝。
- 只接 OCR：只能覆盖照片内文字，无法覆盖普通生活照，不能作为完整方案。
- 直接换成图文生成模型：可作为 4.0l 选型候选；尚未评估或批准，不能假定兼容当前预算。

## 后果

Phase 4 增至 27 个任务。照片直接创作仍是明确未交付的产品能力，由 4.0l 承担；4.0k 的文本功能证据继续有效。新增持久派生数据和本地推理成本须在实现阶段验证；本轮仅同步文档和任务，不改代码、模型或测试门禁。
