# ADR-026：统一创作库与页面无关任务

**状态**：已接受，待实现验收
**日期**：2026-09-09
**决策人**：用户批准，Codex 记录

## 背景
手动创作结果只在页面内存中，离开页面取消生成；已有月/年报告则拥有独立持久存储。

## 决策
采用 `4.0m-creation-library-proposal.md` 的十条闭环验收。首页提供统一入口；手动任务由 composition-owned Actor 和 TaskQueueActor 持有，页面只订阅。提交先持久化有界 ID/模板/语言/版本描述，再入队；完整成功输出独立保存，失败/取消/中断可见并仅手动重试。首版允许 Echo 内页面切换，不保证系统挂起后继续推理。进程中断从头重建输入，不伪装 KV 续传。

来源关系覆盖全部贡献输入，存储事务重验当前政策及 Memory 存在性；读取、生成及导出重验。D-005 覆盖作品/任务/来源关系，删除作品不删除 Memory、不写 ExcludedAssets。报告库只投影现有 NarrativeReportActor 数据。保留现有语言、来源、模型与预算门禁，诗歌失败仍是失败。

## 备选方案
仅移除 onDisappear 取消不能保证持久结果与删除边界，未采用。系统后台长期推理不在本次范围，不请求额外通知权限。

## 后果
新增领域持久表、队列任务类型及 UI 薄适配器；重启后结果可读，未完成任务由用户重试。已有 4.0l 仍处审查，用户明确授权在其已提交代码之上开发 4.0m，不将 4.0l 标为完成或绕过其验收。

## 2026-09-09 Live Review 修订
打开创作库条目只读取既有状态，不触发生成或重试；列表和详情均须由明确的“重试”按钮才发起重试。列表行内操作必须使用独立点击区域，不能与行导航共享默认 List 按钮响应。由创作库进入详情后，“查看创作库”返回已有列表，禁止继续堆叠同类创作库页面。

### 新创作入口交互修复
从照片详情新建创作时，生成页仅在用户点击后以原生 sheet + 独立 NavigationStack 展示创作库；不得在生成状态中内嵌指向创作库的 NavigationLink，避免创作库/创作详情导航链参与状态切换造成布局卡死。创作库来源的详情继续 dismiss 返回已有列表。生成期间返回、切换标签与浏览创作库不取消任务。16 Pro 已验证真实照片生成中的完整路径，证据见 4.0m-implementation-evidence.json。


### 创作库统一删除入口（2026-09-09 用户要求）
手动作品与月/年报告统一提供行末原生“更多操作 → 删除”菜单及左滑删除；关闭整行 full-swipe 直接执行，两个入口都先呈现确认框。确认前不写入、不取消任务；确认信息明确只删除作品、保留来源记忆，手动创作存在活动任务时先协作取消。月/年报告复用 NarrativeReportActor.deleteReport，将对应周期置为 invalidated，不自动生成回来。

删除成功后刷新列表；失败保留条目并显示独立错误提示，不被周期刷新清除，也不声称删除成功。同一条目删除操作防重复。作品删除不删除 Memory/原始照片、不写 ExcludedAssets；手动任务来源关系及 PendingOperations/TaskProgress 沿既有删除触发器清理。生成中删除须验证无迟到 publication。
