## R1 — P1: Retry can recreate an entry after deletion
`Echo/Core/Actors/CreationLibraryActor.swift:78–82`, `:54–67`, `:91–94`; `CreationLibraryStorage.swift:48–60`.

`retry` reserves an ID only in the actor's own set, then awaits record loading, runtime recovery and policy access. `delete` does not participate in that reservation. A deletion can complete after retry has read its record but before schedule inserts it. The request UPDATE then affects zero rows, which is ignored, and insertCreationRequest treats absence as a new submission: the same work and source rows are recreated. The runtime-recovery await provides a concrete extended interleaving window. This violates confirmed deletion and the ADR-026 requirement that deleted creations stay deleted.

Fix: serialize/tombstone same-ID deletion and submission/retry; make retry a conditional transition of an existing record rather than an insert-if-absent path. Regression: hold runtime retry after reading the failed record, delete it, release the hold, and assert no recreation, queue ownership or late output. Finding is based on control-flow analysis, not a newly executed race test.

## R2 — P2: Storage rejects supported source aliases
`Echo/Core/Actors/CreationLibraryStorage.swift:106–109`.

The storage authorization check compares raw Memory.sourceType directly with authorizedSourceTypes. Existing pipeline authorization maps text to note and video_frame/video_audio to video through SearchPipeline.normalizeSourceType. A valid legacy/canonical text source under note permission can pass CreativePipeline but fail the new library submission/read path. Current library tests insert note directly, so do not exercise this compatibility boundary.

Fix: use the existing normalization function consistently at the storage policy boundary, while continuing to reject unknown or unauthorized types. Add canonical text/video alias and revoked-policy cases. This is a source-policy compatibility finding, not a request to grant additional access.

## R3 — P2: System resource deferral is converted into L2 failure
`Echo/Core/Actors/CreationLibraryActor.swift:143–164`.

CreativePipeline deliberately propagates NarrativeReportError.resourceDeferred for low power, thermal pressure or a busy shared model session. CreationLibraryActor routes that error through the generic failure branch, persists generation-failed and inserts PendingOperations. Temporary resource unavailability therefore becomes a failed creation requiring manual L2 replay, contrary to AGENTS.md section 4.3: “资源延后非 L2”.

Fix: retain an honest resource-deferred state and legal rescheduling policy without treating it as L2, automatically replaying real L2 errors, or promising continuous background inference. Test both resource recovery and durable genuine failure behavior.
