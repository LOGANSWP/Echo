# 4.0l 功能闭环优先：原生研究检查点

**后续状态**：原生输入和中英文组合已验证，见[新检查点](4.0l-native-input-review.md)。确切本地 App 工件已形成[审批包](4.0l-approval-packet/README.md)，当前等待工件使用批准；本页此前状态是历史记录，质量优化不作为开工前提。

**2026-09-09：Swift/Core ML 已实际完成受控图片→描述；尚未接入 Echo 生产照片流程。**

## 人类决策

> 我们需要明确一点，现在项目初期构建闭环阶段不需要追求高精确度，首先是追求功能闭环

当前执行重点是让真实图片经过真实本地模型，进入创作、来源跳转及复制/分享流程。描述精细度、事实准确率和文采单独记录为后续优化项，不再作为继续原生转换与功能接线的前置门槛。此前因 27 次参考输出中的质量问题而停止 SmolVLM 的推进结论已撤回；原始失败输出不改写为通过。

## 已执行的功能验证

- 按原研究授权恢复同一固定 SmolVLM-256M 源，14 文件、517,904,565 bytes 全部重新校验；只有一份源，没有下载更大候选。见[恢复记录](4.0l-source-restoration.json)。
- 真实权重拆为视觉编码器/投影与带 60 个 KV state 的文本解码器。固定 512 图像、64 个视觉 token、context 1024、FP16 Core ML、iOS 18 编译目标。两图各四个解码位置与官方 FP32 图对照，八次 top-1 相同；视觉张量也通过对照。见[转换证据](4.0l-coreml-conversion-2.json)。
- 原生 Swift 6 CLI 在 Mac 上直接调用 Core ML，进程内没有 Python 推理。两张测试图由 Swift 在内存构造，RGB 摘要与独立参考一致，输入均为 83 token；每图 1 次视觉预测和 92 次解码预测，合计 **186 次真实 Core ML 预测**。
- 红圆输出 `In this image there is a red circle.`，蓝圆输出 `In this image there is a blue circle.`。两者各 10 个输出 token（含 EOS），全部与独立 FP32 参考相同；同一提示只改变像素，描述随之改变。
- Native 编译约 0.37 秒、加载约 2.09 秒，两次完整图片描述分别约 **3.98 / 1.61 秒**，均在 60 秒限额内。见[原生结果](4.0l-native-results.json)、[参考结果](4.0l-native-reference.json)。
- Swift 使用 `-swift-version 6 -strict-concurrency=complete -warnings-as-errors` 编译通过。没有修改 App Bundle、Core、签名、CI 或生产依赖。

这是功能与转换执行证据，不是普通照片准确率或正式内容质量评测。Native 当前消费固定、已与官方 tokenizer 校验的 prompt token；输出使用 Swift ByteLevel 解码。任意文本原生 tokenizer、矩形图片/方向/填充预处理、实际取消/恢复、生产 Actor/存储与 PhotoKit 链路仍待完成。

第一次转换发现当前 Transformers 已将 `rope_theta` 移入 `rope_parameters`，没有产生转换包；按本地已安装实现修正后第二次完成。第一次异常保留在[历史报告](4.0l-coreml-conversion.json)。第一轮外部资源监控受沙箱进程枚举限制，子进程随后自行失败退出；只读确认无残留进程后，在允许监控的环境执行第二轮。未把未监控的第一次尝试记为资源通过。

## 剩余工作与边界

继续使用当前候选推进工程链路，更大 Qwen3.5 提议延后。英文机器观察可作为标明真实语言/模型版本的中间素材，后续最终创作输出继续消费 `preferredLanguage`；尚未验证这条组合路径，不宣称视觉模型已经支持中文。

在生产装配前补齐原生输入处理、运行时边界、许可/NOTICE/SBOM 和可审阅的确切工件与资源材料。原研究授权不等于 App 使用/分发批准。之后按 ADR-025 接入独立描述/OCR 存储、有界队列、新旧照片处理、当前授权校验、创作/报告、D-005 和真实 PhotoKit 功能验证。

`4.0l` 保持 `in_progress`；DEF-79-001 保持 open。内容质量、实机和发布资格独立追踪，不假报完成，也不再让内容质量调优阻断当前功能研究。
