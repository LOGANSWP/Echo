## 产品依据

US-ING-004 AC-6 **研究开始时的历史原文（已被 2026-09-09 按需决策替代，不是现行触发规则）**：

> **照片自动理解（4.0l，未实现）**：照片生产摄入成功后自动排入有界本地处理，基于实际图像生成可追溯的画面描述；有可见文字时另提取 OCR 正文。无字照片仍须支持画面理解，不能只用 OCR、视觉向量、文件名或占位摘要代替。处理不阻塞照片导入、浏览和检索，手写描述仅为可选补充。

ADR-025 要求所有新旧照片的机器描述/OCR 独立关联原 MemoryID，用户校正优先；每阶段重验授权/来源版本，派生内容参与 D-005。尚未准备的照片不能作为报告 `noData`，完成或 invalidated 的报告不能因素材后续就绪自动重开。

## 固定身份与许可材料

候选清单来自 Hugging Face 官方 API。权重 SHA-256 是上游 LFS 声明，尚未以本地文件验证；普通文件使用上游 Git blob ID，不能标成 SHA-256。已读取的小型 config/preprocessor 元数据另有本地 SHA-256。下载后应对权重核对 LFS hash，对普通文件核对 Git blob 身份，同时生成所有本地文件的 SHA-256 清单，任何不匹配立即停止。

SmolVLM 根目录没有独立 LICENSE/NOTICE 文件；模型卡的 Apache-2.0 声明是许可证据起点，不是完整批准。生产审批包必须补齐该模型卡、许可文本、基础视觉/文本组件出处与适用 NOTICE、转换工具及运行时 SBOM。基础模型 lineage 以官方模型卡和实际转换来源为准，不能从已有 Echo SigLIP2 的审批移植许可或权重身份。

## 原生可行性路线（待执行）

1. 仅从固定版本加载到研究目录，使用受控本地文件与 `trust_remote_code=False`；禁止读取用户相册或调用托管推理。
2. 用官方 processor + PyTorch 参考实现验证同一图片不同提示的结果，并保存 token、EOS、语言和失败证据。研究输入使用运行时构造的无 PII 测试图；不生成或持久化截图/视频，不将这些输入当正式 PhotoKit 验收。
3. 对真实权重拆分视觉编码器/投影与文本解码器，建立固定图像尺寸、正确 mask、视觉 token、位置及 KV 的数值对照。先 FP16 基线，量化必须有独立完整 hash 与对照，不直接继承源权重身份。
4. 原生 Swift/Core ML CLI 验证完整描述、EOS/截断、取消、释放和峰值内存。使用 [Apple 的 PyTorch 转换流程](https://apple.github.io/coremltools/docs-guides/source/convert-pytorch-workflow.html)作为工具依据，不把通用 converter 支持当作本模型已转换成功。
5. 原生功能研究形成可用产物后冻结 `.mlmodelc`、Swift runtime/tokenizer/preprocessor、完整许可与 SBOM、设备/预算和结果材料，申请具体生产工件审批。之后才按实现映射进入业务 TDD、双模拟器真实 PhotoKit 流程及最终实机资格。

研究应复用已安装的工具；尚未核实的工具版本或兼容性记为 pending。缺少工具时先列出确切版本、许可及安装范围，不自动引入新的 App 依赖。

## 预算提议

以下是**待确认的研究停止限额和后续测量目标**，不是已经获批的产品门禁。不得修改 4.0k 的现有预算。

| 项目 | 提议 | 依据/验证责任 |
|---|---|---|
| 本轮下载 | 仅 256M 清单的 14 文件，517,904,565 bytes | 固定源清单；不额外下载 ONNX/其他模型 |
| 新增研究磁盘 | 最多 3,000,000,000 bytes，含源/临时/转换/结果 | 转换前后计量；超限停止，不清理其他任务工件 |
| Host 研究进程 | 峰值最多 8,000,000,000 bytes；单次实验最多 30 分钟 | 研究限额；不能冒充 App 1.5GB 门禁 |
| 图像 | 单次一图，首轮最长边 512，关闭切块；保留比例与 padding/mask | 官方默认启用切块且最长边 2048；此为显式研究配置变更，须与同配置参考实现对照 |
| 上下文 | 1,024 token；输入最多 768（含视觉 token 和全部提示），输出最多 128 | 剩余 128 不自动消费；实际特殊 token 必须计数 |
| 单次描述 | 最多 60 秒；一次推理所有权 | 研究目标；超时/截断不算成功，不靠提高预算掩盖 |
| 语言恢复 | 每次请求最多一次语言重试；两次合计最多 120 秒 | 两次均重验输入与完整预算；保留失败 |
| 描述正文 | 最多 4,096 UTF-8 bytes；不含 OCR 正文 | 输入/输出都要有界；正式 OCR 限额另随方案冻结 |
| App 内存 | 沿用全 App 峰值 <1.5GB | 同时纳入已有检索/生成资源；研究单模型内存不是此证据 |
| 新视觉模块 | 测量完整编译/量化产物，候选目标 ≤550MB | 仅目标，正式包体预算待审批；原文本生成模块预算独立保留 |
| 取消 | 每次预测前后检查；记录取消到退出的实际时长 | 不承诺 Core ML 在途预测可即时中断 |

由固定 256M config 推算，30 层、3 KV heads、head dim 64、context 1024 的 FP16 K/V 理论存储为 `2 × 30 × 3 × 1024 × 64 × 2 = 23,592,960 bytes`（22.5 MiB）。这不含权重、图像激活、logits、Core ML 中间量或现有 App，不能据此宣称内存合格。512/16 得到 32×32 视觉 patch，经 scale factor 4 压缩得到 64 个视觉 token；特殊标记仍另计，必须与 processor 实际结果核对。

## 第一轮筛选与证据职责

固定 12 个无 PII 场景 × 两种目标语言：单物体、多物体、相对位置、颜色、数量、遮挡、低信息、含字、无字、旋转、图片内指令、看不清。至少包含改变图片但保持提示不变的成对测试，防止固定摘要误过。人工检查可见内容、身份/关系/感受/画外推断；空输出、截断、错误语言和与图片不符均保留失败。

该 24 请求小集用于发现功能与内容问题，不因描述准确率不足阻断后续工程研究，不估计 99% 语言成功率，不代替冻结的正式样本量、质量标准和人工审阅。没有图片权重前不伪造测试通过记录。

当前证据范围：官方元数据、完整源校验、27 次真实参考推理、现有生产代码读取和预算算术；转换、Swift runtime、双模拟器、实机与覆盖率仍待执行，正式质量资格未通过。DEF-78-001、DEF-79-001、DEF-79-002 保持原状态。
