# 4.0m 统一创作库与页面无关的生成任务

状态：需求方案，尚未实现。来源：2026-09-09 用户提出统一查看 AI 创作结果，避免一直停留在创作页面。待明确 App 切到后台/锁屏的交付范围；不将其与离开当前页面混为一谈。

## 当前缺口

- `CreationViewModel.creation` 仅保存页面内结果；`onDisappear()` 取消 `generateTask`。
- 月报/年报已有持久报告与结果 library；手动信件、诗歌、报告、时间线没有对应的持久作品库。
- 因此只增加列表或移除取消代码不能完成需求：仍缺少任务所有权、结果落库、重启与删除边界。

## 产品方案

首页增加“创作库”入口，统一投影手动作品和已有月报/年报，提供全部、进行中、已完成、失败筛选。用户选择素材和模板并提交后，立即出现任务记录；可以返回首页、搜索或照片详情。完成结果自动保存在本机，再次打开或重启后可查看，不重新推理。列表按创建时间排序，显示模板/报告周期、时间和真实状态；有新完成作品时显示 App 内标记。

正在执行和排队的条目只展示真实状态，不展示占位正文或虚构百分比。失败保留原因和用户发起的重试；取消保留明确的已取消状态。完成结果复用现有阅读、来源跳转、正文复制、PDF/Markdown 与系统分享能力。

## 首个闭环验收

1. 点击生成后，先持久创建唯一任务记录，只有队列接管成功才显示已提交；多次点击不产生重复任务。
2. 离开创作页或切换 Echo 内页面不取消任务，页面只订阅状态；显式取消才请求队列协作终止。
3. 手动创作由 App composition 管辖的 Actor 与 TaskQueueActor 拥有，和照片理解/报告共享现有串行资源边界。生成前继续检查所选照片的当前机器描述或手写描述门禁。
4. 模型、语言、格式、来源校验通过且结果持久化成功后才显示已完成。失败不生成空白作品，不自动重试 L2；已有成功作品不会被后续失败覆盖。
5. 已完成结果和完整贡献来源关系独立于 Memory 保存；不创建伪用户记忆、不自动写回 Notes，不自动过期。月报/年报只读取既有权威存储，不复制第二份报告正文或周期状态。
6. App 退出/进程被终止时保留已完成结果；未完成任务显示中断/待恢复，由用户明确恢复或重试。未提交到可靠 checkpoint 的模型 KV/正文不伪装为可继续进度。
7. 重试与恢复重新检查当前授权、来源版本、排除项和模型配置，重建输入；任务描述只保存有界版本化 ID/配置，不保存原文、像素、KV 或授权快照。
8. 删除作品不删除原始记忆，也不写 ExcludedAssets。来源确认删除/从 Echo 移除/全部同意撤销时，相关作品、任务、缓存与关联参与 D-005。来源访问权限变化时，读取与导出仍遵守当前策略；单纯 PhotoKit 不可见不推断来源删除。
9. 所有写入通过 DatabaseManager 管辖的 Actor；任务只对 UI 暴露 Sendable 值类型。审计不包含作品正文/照片/来源 locator。
10. 真实本地模型验证“提交 → 离开页面 → 完成 → 创作库查看 → 退出重开仍存在”；失败、重复提交、取消、来源删除/撤权、持久化失败均有定向测试。模型自身失败应出现在失败列表，不得借作品库掩盖 4.0l 当前诗歌失败。

## 系统后台范围待定

基础范围：在 Echo 内换页面仍继续；App 被系统挂起时不保证 CPU/GPU 继续运行。若用户选择包含切到其他 App/锁屏，则新增系统允许的后台执行机会及 expiration 安全终止/持久恢复验收，不能承诺无限后台运行。系统通知属于独立 opt-in，不为本需求擅自请求权限。

## 受影响实现

- Home：创作库入口与完成标记。
- Creation：持久作品列表/详情、任务订阅、生成提交和重试；移除页面对已提交领域任务的取消所有权。
- Core：手动创作任务与作品 Actor、SQLite 表/来源关系、typed queue launcher 与恢复接线、D-005 清理。
- 复用：CreativePipeline、生成语言/来源校验、NarrativeReportActor、现有导出协调器及预算配置。

## 任务安排

建议独立任务 `4.0m`，关联 US-SYN-003/004、US-SYS-001、US-PRV-007；与正在进行的 `4.0l` 模型/照片输入闭环分开验收。正式纳入规格、依赖和实现范围后再开始编码，不能把一个页面列表当作完整后台创作交付。
