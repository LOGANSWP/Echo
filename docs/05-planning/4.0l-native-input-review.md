# 4.0l 原生输入与中英文生成组合

**2026-09-09：原生输入和研究生成组合已通过，确切模型已形成 App 接线审批包。生产 PhotoKit/存储/UI 尚未实现。**

本检查点继续执行用户要求的“功能闭环优先”，沿用同一获批研究候选和 3GB 磁盘限额，没有扩大模型下载范围。此前的[固定输入研究](4.0l-functional-research-review.md)保留为历史证据；本轮已去掉 Native 流程对预先准备 prompt token 的依赖。

## 已完成

1. **Swift 原生 tokenizer**：先运行失败的接口骨架，再实现固定 SmolVLM ByteLevel BPE、Digits 拆分、无 NFC 正规化的字节保持和受控提示框架。103 个官方对照与 4 个输入预算拒绝通过。上游固定词表缺少部分 byte symbol，原生实现显式拒绝这些输入，不静默丢弃。含 `<image>` 等协议文字的普通输入不升级成协议 token。见[测试结果与样本](4.0l-native-helper-tests.json)。
2. **原生图片输入**：先记录接口骨架失败，再实现 ImageIO 头部检查、尺寸/字节限额、方向变换、等比缩小、sRGB/透明白底、归一化后填充和 patch position/mask。八种方向加四组大小共 12 个测试通过；无效/超限输入 3 个拒绝通过。测试图只在内存编码为 TIFF，不保存媒体。
3. **完整原生调用**：Swift 构造并编码正方形、横图、竖图，ImageIO 解码，Swift 自行生成 83-token 提示，调用实际视觉模型及状态解码器。三图均得到带 EOS 的真实描述，每图 93 次 Core ML 预测，约 1.5–1.9 秒。[原生结果](4.0l-functional-generate.json)。
4. **实际取消**：在一次真实视觉预测后取消当前 Task；未调用文本解码，也没有输出描述结果。[取消证据](4.0l-functional-cancel-after-vision-resources.json)。不把这一测试写成 GPU 预测中途可抢占或实机取消时延通过。
5. **精确编译工件**：两图编译为 iOS 18.0 目标的 `.mlmodelc`，共 10 文件、514,162,725 bytes；随后直接加载该目录重复三图完整流程，生成 token 与上一轮全部相同，完整文件 hash 前后不变。[编译身份](4.0l-compiled-models.json)、[直接加载结果](4.0l-functional-generate-compiled.json)。
6. **中英文生成组合**：消费前面实际生成的两条机器描述，分别请求 zh-Hans/en-US，共四次旧有 Qwen3 原生生成器调用。真实 JSON、EOS、来源 allow-list 与 NaturalLanguage 正文语言检查 4/4 通过；没有手写 caption 替换模型结果。[生成输出](4.0l-generation-bridge.json)、[结构/来源/语言检查](4.0l-generation-bridge-validation.json)。

全部新增 Swift 研究程序使用 Swift 6、`-strict-concurrency=complete`、`-warnings-as-errors` 编译。没有运行业务单元测试或阶段集成任务；研究 helper 测试不计入 App 测试覆盖率。

## 真实限制

- 英文生成重复了同一段落，记录为质量优化项；没有为此修改真实输出、换模型或停止功能推进。
- 两张桥接图片表达同一简单场景，四次语言参数调用不是四个独立质量案例。普通生活照片、复杂事实准确率仍未验收。
- 组合在顺序启动的两个原生研究进程中完成；视觉进程退出后才启动生成进程。它证明输入可组合，不证明 App 同进程资源释放或已有生产依赖图完成。
- 图片预处理目前验证内存 TIFF 及方向/缩放合同；真实 PhotoKit JPEG/HEIC、授权/删除竞态、旧照片补处理、存储、报告周期和 UI 仍需在 App 接线阶段验证。
- Swift 预处理采用有版本的 ImageIO 路径，不冒充上游 Pillow 在任意缩放/色彩空间下像素完全相同。固定正方形源对照和后续输入/mask 测试各有明确证据范围。
