## 结论
当前创作库实际失败分别为诗歌 `deadline` 和中文信件 `language`；被取消的验证任务不计入模型失败。先前 UI 交互检查不代表生成能力通过。

## 可复现误拒
使用非个人画面描述（狗站在沙地，背景有山）、当前生产信件 Prompt v12 和真实获批 bundled 模型，在规定 iPhone 17 Pro / iOS 26.5 串行测试：
- 简体中文模型正文“一只狗站在沙地上，背景有山。”，40.55 秒，59 output tokens；`detectLanguage` 返回 `uncertain`，`bodyMatches` 拒绝。
- 英文正文“A dog is standing on the sand, with mountains in the background.”，26.91 秒，64 output tokens；`en-US`，校验通过。
- 中文一项断言失败、英文通过。诊断不伪装绿色测试。原始合成输出及指标见同名 JSON。

`LanguageAligner.detectLanguage` 要求最可能语言置信度至少 0.9，否则返回 uncertain；`bodyMatches` 要求结果严格等于目标语言；`alignEnvelope` 逐段检查，最多重生成一次，再报 languageFallback。确定的中文短句也可能因此被误拒。具体 iOS 18 失败任务的正文没有持久化，不将本次合成输出声称为其原始输出；但误拒机制已独立复现。简繁转换不是此次断言失败的首个阻断点。

## 独立超时
16 Pro 当前诗歌记录为 deadline。DEBUG Simulator 手动创作已获批每调用 120 秒、每请求 240 秒，不能再无限重试。四行诗包含示范 Prompt、四个结构化段落及来源，工作量高于单段信件；当前 CPU 模拟器耗时是独立失败路径。已有信件两次完成调用也可累计超过两分钟后被校验拒绝。未使用新的诗歌复现来伪造更精确的耗时归因。

## 质量与功能边界

## 红圆剩余失败的确切根因（v18 修复）
旧任务在 v17 重新点击重试后复现：112.26 秒、256 tokens、outputLimit。独立 17 Pro 使用同样的非个人合成图片描述，先复现 deadline，再通过无正文结构计数证实 548 字节里 473 字节为空白，97.54 秒用满 256 tokens 仍未完成 JSON。原来的 grammar 允许在结构字段之间无限追加格式空白，短诗正文长度限制没有约束这条路径。

修复为 compact manual zh-Hans scope 的紧凑 JSON 解码；标准模式仍接受合法格式空白，正文空格不受该规则影响。回归覆盖每个 UTF-8 前缀、合法正文空格、结构空白拒绝、来源和长度边界。创作库新增 output-limit 类型及中英文提示，失败仍只手动重试。初轮修复真实生成狗图 41.34 秒/56 tokens，红圆 27.48 秒/51 tokens，结构空白均为 0；红圆重复诗行属于后续质量待办，不代表功能生成失败。最终测试和 16 Pro publication 以 4.0m-implementation-evidence.json 的 redCircleFunctionalFix 为准。
