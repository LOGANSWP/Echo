# Echo · 回响：数据流全链路技术说明文档

**版本**：v1.5

**生效日期**：2026-09-07

**适用架构**：Cognitive Pipeline + Observable ViewModel + Actor Isolation

**对应规格**：Echo v4.6 全量用户故事与验收标准规格书

本文档详细描述数据在 Echo 各组件间的流动路径，涵盖用户交互、后台任务、错误处理、断点续传等全链路行为。所有流程均遵循 **本地优先、隐私可审计、任务可中断/续传** 的原则。

**数据流特点**：

- **单向数据流**：UI → ViewModel → Pipeline → Actor → 存储。结果通过 `AsyncStream` 反向传递至 ViewModel，驱动 UI 更新。
- **Actor 隔离**：所有可变状态（数据库、队列、排除表）由 Actor 独占，避免数据竞争。
- **串行化保证**：`TaskQueueActor` 确保索引构建与数据同步互斥执行。

### 1.1 首次体验与渐进式权限数据流（Phase 4 `4.0f`）

```mermaid
flowchart TD
    Launch[首次启动] --> Consent{PIPL 同意?}
    Consent -->|拒绝| Exit[退出引导，不访问受保护数据]
    Consent -->|同意持久化成功| PhotoChoice{用户选择连接照片?}
    Consent -->|持久化失败| ConsentRetry[停留并显式重试]
    PhotoChoice -->|跳过| Language[语言选择与本地模型加载]
    PhotoChoice -->|连接| PhotoKit[仅请求 PhotoKit]
    PhotoKit --> Language
    Language --> App[进入 App]
    App --> DeliveryOptIn{用户显式启用系统通知投递}
    DeliveryOptIn --> Notification[请求通知权限并复读设置]
    App --> AwakeningOptIn{用户显式开启唤醒功能}
    AwakeningOptIn -->|地理围栏| WhenInUse[请求 When In Use]
    WhenInUse --> BackgroundChoice{用户需要终止态区域唤醒?}
    BackgroundChoice -->|第二次明确确认| Always[请求 Always]
    AwakeningOptIn -->|健康上下文| HealthKit[请求最小 HRV read scope]
    AwakeningOptIn -->|纪念日| Anniversary[不请求系统权限]
```

- PIPL 同意写入 `ConsentStoreActor` 成功之前，不显示或执行 PhotoKit 等受保护请求；写入失败不得先推进 UI。
- 首次启动不得自动串联 PhotoKit、notification、location 与 HealthKit；系统 prompt 只能由与当前用途直接对应的用户操作触发。PhotoKit 的 `Not Now` 是无系统调用的本地跳过。
- 通知只由独立投递 opt-in 请求。geofence/emotion/anniversary 开关不隐式请求通知；通知 denied 时仍允许生成 App 内唤醒卡。
- 地理围栏先请求 When In Use；终止态后台区域唤醒需要说明差异后的第二次明确 Always 请求。每个 async 请求必须等待授权回调或复读最终状态，禁止调用 API 后立即返回旧快照。
- HealthKit 只记录请求是否完成与样本是否可读。不得使用 `authorizationStatus(for:)` 或请求 completion 的 success 推断 HRV read granted/denied；无可读样本时走 7 天查询/感受的本地回退。
- 三个唤醒偏好、通知投递意图与 HealthKit request lifecycle 通过 `AwakeningPreferenceActor` 写入本地 SQLite；系统授权状态不入库。重启只恢复偏好与 request lifecycle，不自动调用任何 request API。
- 拒绝、限制授权或跳过不会阻断其余离线能力，也不会在再次启动时自动重复请求。系统设置入口只在 denied/restricted 后由用户主动触发。
- UserPolicy 只保存真实来源授权，权限拒绝不得被迁移或兼容逻辑自动恢复。详见 ADR-018。

## 2. 用户发起检索数据流（SearchPipeline）

### 2.1 流程时序图

```mermaid
sequenceDiagram
    participant View as SearchView
    participant VM as SearchViewModel<br/>(@MainActor)
    participant SP as SearchPipeline
    participant PA as PrivacyActor
    participant FA as FeedbackActor
    participant VA as VectorStoreActor
    participant Audit as AuditLog (SQLite)

    View->>VM: 用户输入查询 "开心的事"
    VM->>SP: search(query: "开心的事")
    SP->>PA: validate(operation: .search)
    PA->>PA: 检查 UserPolicy 授权
    PA-->>SP: PrivacyCheckpoint (含 traceID)
    SP->>Audit: 写入审计记录 (.retrieval)
    SP->>FA: computeAdjustment(for: memories, query:)
    FA->>FA: 从 FeedbackStore 读取反馈<br/>筛选 cosine ≥0.80 的记录<br/>计算衰减系数并求和，截断至 [-0.5,0.5]
    FA-->>SP: adjustment = +0.3
    SP->>VA: 执行 ANN 检索 + 元数据过滤<br/>(时间/标签/地点; 人物过滤已移除 R-5.3)
    VA-->>SP: 候选记忆列表 (原始相似度)
    SP->>SP: 应用重排: finalScore = cosineSim + adjustment
    SP->>SP: 低置信度标记 (<0.6 且跨语言匹配)
    SP-->>VM: 返回 SearchResult (含锚点、置信度)
    VM->>View: 更新 @Observable 属性，渲染列表
```

### 2.2 关键节点说明

| 节点            | 职责                                               | 错误处理                                       |
| --------------- | -------------------------------------------------- | ---------------------------------------------- |
| `PrivacyActor`  | 验证当前操作是否违反用户授权（如检索排除的数据源） | 若拒绝，直接返回 `.denied` 空结果，审计标记    |
| `FeedbackActor` | 读取所有反馈记录，计算调整值                       | 读取失败时返回 0，记录 L2 错误至 `PendingOps`  |
| `VectorStoreActor` | 向量检索 + 标量过滤                                | 超时 (2s) 返回部分结果，标记 `.partialResults` |
| **输出**        | 包含记忆 ID、原始文本/媒体、溯源锚点、置信度提示   | 低置信度时 UI 显示预设文案                     |

### 2.3 Discovery 展示映射（Phase 4 `4.0a`）

SearchPipeline 返回的顺序、`memoryId`、partial/low-confidence 与反馈绑定是领域真相，Discovery 布局只能执行以下只读映射：

1. UI-adjacent source adapter 在当前 UserPolicy 下验证来源仍获授权、未排除且可解析；失效项目不进入 `displayableResultCount`，但 UI 不回写或复制排除规则。
2. adapter 按真实来源 metadata 映射稳定 Focus 路由、aspect ratio/摘要，并生成展示专用 `presentationKind`：来源可解析的照片/视频或去除首尾空白后非空且不超过 160 个 Swift `Character`（扩展字形簇）的可独立理解摘要为 `scanEligible`；更长或需要连续阅读的备忘录、语音转写/正文为 `continuousReading`。
3. 结果不足 6、两类平票、`continuousReading` 占多数、Accessibility Dynamic Type、VoiceOver 开启或可用内容宽度不足 340pt（2 × 164pt + 12pt）时使用单列；全部条件满足且 `scanEligible` 严格多于半数时才进入 adaptive masonry。
4. masonry 仅计算几何位置，输入数组和 VoiceOver 顺序保持 SearchPipeline 原顺序；反馈动作继续携带原 `memoryId`。

Home 的 `visibleMemoryCount` 使用相同“策略允许 + 未排除 + 来源可解析 + 稳定 ID/Focus 路由 + 真实展示内容”定义。0 条时只有 ProgressActor 存在真实活跃扫描任务才显示 determinate 进度；没有任务、任务已完成或尚未授权时显示真实授权/分享导入状态，不生成假进度。Home 最近导入可通过现有 canonical repository 的无副作用只读查询获取；媒体比例/位置经已授权 source adapter 解析，禁止新增第二份领域存储。

## 3. 数据源接入与记忆摄入数据流（IngestPipeline）

### 3.1 流程时序图（以图片为例）

```mermaid
sequenceDiagram
    participant PhotoKit as PHPhotoLibrary
    participant IP as IngestPipeline
    participant EA as ExcludedAssetsActor
    participant TQ as TaskQueueActor
    participant PR as ProgressActor
    participant Model as ModelLoader (Core ML)
    participant VA as VectorStoreActor
    participant Audit as AuditLog

    PhotoKit->>IP: 新照片通知 (BGAppRefreshTask)
    IP->>TQ: enqueue(task: .ingestPhoto(assetId))
    TQ->>PR: save(taskId, progress=0)
    loop 每张待处理照片
        IP->>EA: contains(assetId:)
        alt 已排除
            IP->>PR: 跳过该资产，更新进度
        else 未排除
            IP->>Model: 加载 SigLIP2 模型 (若未加载, R-5.1 转换中)
            Model-->>IP: 向量 (512d)
            IP->>VA: 开始事务
            IP->>VA: 写入向量 + 元数据 (EXIF, 时间戳)  # 人物标签已移除 (R-5.3)
            IP->>VA: 提交事务
            alt 写入失败
                VA-->>IP: 回滚
                IP->>IP: 错误升级为 L2，写入 PendingOperations
            end
        end
    end
    IP->>PR: 更新进度 (processedCount/totalCount)
    IP->>PR: delete(taskId) (完成后清理)
    IP->>Audit: 记录 .imageIngested (含 privacyBlurApplied=false)
    IP->>TQ: 任务完成，释放队列
```

### 3.1.1 审计双写模式（Double Audit Pattern）

图片摄入产生两条审计记录，分工明确：

1. `PrivacyActor.validate()` 内部写入 **通用事件**（best-effort `try?`）
   — 例如 `.memoryIngested`，仅含 `traceID` + `policyVersion`，记录“发生过一次摄入操作”
2. `IngestPipeline.ingestImage()` 成功后写入 **特有事件**（best-effort `try?`）
   — `.imageIngested`，额外含 `sourceType=photo`、`privacyBlurApplied=false`、`elapsedMs`

两次写入均使用 `try?`（L1 瞬态语义）：审计写入失败不阻断已成功的摄入操作。通用事件覆盖所有 Pipeline 类型（文本/图片/视频），特有事件补充操作细节。

### 3.1.2 ExcludedAssets Fail-Closed 模式

`ExcludedAssetsActor.contains()` 查询使用 `do-catch`（**非** `try?`）：

- DB 正常 → 检查 assetId 是否在排除表 → 已排除则抛出 `assetExcluded`
- DB 异常 → 抛出 `excludedAssetsLookupFailed`（L2），**阻止摄入**

原则：宁可因 DB 错误阻断摄入，也不让已排除资产静默通过（`try?` 会将其判为“未排除”而放行）。

### 3.2 特殊流程：视频摄入

视频摄入分为画面关键帧 + 音频轨道两步：

1. **关键帧向量化**：每秒 ≤2 帧，每帧同图片流程。
2. **音频转写**：调用 `ASREngine`（`WhisperASREngine`，whisper.cpp v1.9.2 真实转写，3F.3b）转写文本，然后走文本记忆摄入流程（与备忘录相同）。运行时链路：`WhisperASREngine` → `WhisperRuntimeBridge` → `NativeWhisperCInterop`（`whisper_init_from_file_with_params` + `whisper_full`）。
3. **关联**：画面向量与音频文本向量通过 `memoryGroupId` 关联。

> 🔧 **摄入方式修订（Phase 3F / ADR-006 + ADR-008，2026-08-04）**：备忘录与语音备忘录的文本摄入**仅通过 Share Extension 用户主动分享**进入（share-only）；自动读取系统 Notes / Voice Memos（MKMapItem / NoteStore / SFSpeechRecognizer 自动路径）为私有/不存在 API，移出 v1。视频/图片仍走 PhotoKit 授权范围内读取。

> 📌 **实现状态（3F.3b，2026-08-09）**：Whisper 真实转写已可用。`ASREngineProtocol` 新增**文件 URL 输入契约** `transcribeFile(at:)`（DEF-51-002），Share Extension 分享的音频文件可直接转写；PHAsset ID 语义保留给视频轨道，统一于 3F.5。转写文本走文本记忆摄入流程。

> 📌 **生产摄入路径（3F.5，2026-08-10）**：`IngestPipeline.ingestProductionPhoto/Video/SharedText/SharedAudio` 经 `CanonicalMemoryRepositoryActor.commit`（canonical + representation + FTS + 每代向量存储单事务/补偿回滚，US-ING-006）写入，向量落地由 `GenerationRegistryActor` 活跃路由（ADR-010）解析到 `text_dense/e5-v1` / `vision_dense/siglip2-v1`。长任务经 `TaskQueueActor` 串行入队（ADR-011），进度经 `ProgressActor` 持久化到 `TaskProgress`；任务完成/最终失败清理记录，取消保留进度供重启询问。`SyncPipeline` 生产路由（配置 canonical repository + generation registry 时，CR-3 方案A）`.modified/.added` 替换经 canonical 确定性 ID upsert + 活跃路由向量写入（不再写单一遗留 store），`.removed` 删除经 `deleteMemory` 事务清除（D-005）。AppDelegate 装配真实服务（E5/SigLIP2/Whisper）+ 单一 canonical repo + generation registry + TaskQueue，无 StubEmbedder/StubASR。

> 📌 **生产检索路径（3F.6，2026-08-11）**：`SearchPipeline.search` 经 `SearchChannelAdapters` 逐通道解析 `ActiveRouteSet` 对应代的 `VectorStoreActor`（text_dense E5 384d / vision_dense SigLIP2 768d / ocr_text / lexical，独立向量空间），各通道结果按 RRF 融合并以 ID-keyed `metadataByID` 回填元数据（DEF-34-001）；通道超时/空索引 → `timedOut` 部分结果（US-RET-008），L3 路由缺失以 error 区分（DEF-34-002）。`SearchResultCacheActor` 提供 policy-aware TTL 缓存（键含 policyVersion/modelVersion/queryHash，US-RET-007）。追问查询维护 FIFO 历史 ≤10 轮并携带上轮 `memoryIds` 隐式过滤，写 `.followUpQuery` 审计（US-RET-005 AC-1/2/4/5，AC-3 延后 DEF-58-001）。`FeedbackActor.computeAdjustment` 按 `queryText` 条件化计算反馈重排（US-FBK-001 AC-4），`FeedbackPipeline` 解析活跃 route 后传递 `generationId`（ADR-010 决策 4），L2 反馈失败构造 `PendingOperation` 写入 `PendingOpsActor`（DEF-37-001，可见 + 手动重试）。跨 App 检索经 `CrossAppIntentParser`（health+memory / location+photo 意图）→ `ProductionCrossAppFusionEngine` 逐源授权（未授权源不调用 provider）、按解析时间窗口对齐融合、保留来源标签并写 `.crossAppSearch` 审计（US-SRC-010）；`BoundedReranker` 对主观描述做有界重排（US-SRC-011）。`searchCanonical` SQL 增加 `ORDER BY rank` 于 LIMIT 之前（DEF-56-006）。

### 3.3 错误与重试

- **L1 瞬态**（如 PHPhotoLibrary 繁忙）：指数退避重试 3 次。
- **L2 可恢复**（如磁盘不足）：写入 `PendingOperations` 表，等待用户手动重试。
- **ExcludedAssets 查询失败**（fail-closed）：`do-catch` 捕获 DB 错误后抛出 L2，阻止摄入而非静默放行；确保排除表不可用时资产不会泄漏。
- **模型加载失败**：`ModelLoader` 抛出 L3 阻断，停止摄入并引导用户修复。

## 4. 数据源变更自动同步数据流（SyncPipeline）

### 4.1 触发方式

| 数据源           | 检测方式                                                     | 降级策略                         |
| ---------------- | ------------------------------------------------------------ | -------------------------------- |
| 相册 (照片/视频) | `PHPhotoLibraryChangeObserver`                               | 无降级                           |
| 备忘录           | 前台对比 `lastUsedDate` + 哈希（若 >100KB 或内存低则仅对比时间戳+大小） | 哈希跳过时标记 `.hasHashSkipped` |
| 日历             | 前台对比 `lastModified` 时间戳，`EKEventStoreChangedNotification` 仅辅助 | 无                               |

### 4.2 流程时序图

```mermaid
sequenceDiagram
    participant System as iOS 系统通知
    participant SYP as SyncPipeline
    participant TQ as TaskQueueActor
    participant PR as ProgressActor
    participant EA as ExcludedAssetsActor
    participant VA as VectorStoreActor
    participant IP as IngestPipeline (复用)

    System->>SYP: 变更通知 (assetId: old, new)
    SYP->>TQ: enqueue(task: .sync(assetId))
    TQ->>PR: save(taskId, progress)
    SYP->>EA: contains(assetId:)
    alt 已排除
        SYP->>PR: 跳过
    else 未排除
        SYP->>VA: 开启事务
        SYP->>VA: 删除旧记忆 (向量+元数据)
        SYP->>IP: 重新摄入新内容 (调用 IngestPipeline)

        SYP->>VA: 提交事务
        SYP->>PR: updateProgress
    end
    SYP->>PR: 完成任务，删除进度记录
```

### 4.3 冲突处理（L4）

当后台同步过程中用户正在手动编辑同一条记忆时，`SyncPipeline` 会收到 `userLocked` 标记：

- 阻止删除操作，将该记忆标记为 `conflict`。
- 保留用户编辑的副本。
- 在用户下次打开编辑时弹窗，提供合并界面。

### 5.2.1 生产系统适配器（3F.8，ADR-012）

### 5.5 Focus 编辑、来源删除、引用与报告数据流（ADR-017）

#### 5.5.1 编辑与重新向量化（`4.0e`）

```text
MemoryDetailViewModel.saveEdit
  → PrivacyCheckpoint(.ingest)
  → SyncPipeline.isMemoryLockedForSync / persisted conflict guard
  → normalize title + description + tags + original canonical text
  → prepare new Representation + vectors using active route
  → MemoryUserEditActor / CanonicalMemoryRepository transaction
       publish MemoryUserEdit + Memory timestamp flags + FTS + Representation
  → persist new vectors
  → invalidate search/translation caches and delete superseded vectors
  → .memoryEdited hash-only audit
```

发布提交前失败时必须通过补偿保持旧表示可服务，不允许先删除旧向量再尝试生成新向量；有效文本未变化且表示 ID 相同时必须复用已有向量，失败补偿不得删除原服务向量。发布事务同时写入编辑关系、FTS、representation 绑定、结构化审计和 `memoryEditPostCommit` 待处理清理。事务提交后保存立即成立；旧向量删除与索引持久化作为可重试清理执行，失败时从提交前已持久化的索引检查点恢复内存 store、保留旧向量，并保留 `PendingOperations` 记录供用户手动重试，不得将已提交保存返回为失败。第一次覆盖时间戳保存原 `createdAt` 到 `originalTimestamp`；之后只更新有效 `createdAt`。未保存编辑会话与已经持久化的用户编辑都受冲突保护；冲突保存于 `MemoryEditConflict`，并携带可重放的来源变更参数，不得只保存在 ViewModel。普通保存必须通过同一数据库条件事务确认 conflict 不存在；手动合并的编辑发布、`userLocked=true` 与 conflict 删除必须属于同一事务。选择外部版本时由 SyncPipeline 重放该来源变更，只有新 canonical/representation 发布成功后才通过级联清理用户编辑与 conflict；失败时保留 conflict 供重试。

#### 5.5.2 PhotoKit 原始资产删除 saga（`4.0h`）

```text
Delete confirmation
  → FocusSourceResolver:
       UserPolicy allowed
       PhotoKit authorized/limited + asset visible
       PHAsset.canPerform(.delete) == true
  → PrivacyCheckpoint(.delete)
  → persist MemoryDeletionJournal(
       intentKind = photoLibraryAndEcho,
       sourceDeletionState = prepared,
       phase = planned
     )
  → PHPhotoLibrary.performChanges { PHAssetChangeRequest.deleteAssets(...) }
       (system presents its own edit confirmation)
  → cancelled/denied/failed:
       sourceDeletionState = notDeleted
       keep Echo canonical/vector/cache/ExcludedAssets unchanged
       audit truthful outcome, close intent
  → success:
       durably set sourceDeletionState = confirmedDeleted
       then unlock the existing D-005 cleanup from .planned
  → CanonicalMemoryRepositoryActor.cascadeDeleteFromOriginal
  → D-005 Echo cleanup + no ExcludedAssets write
  → completed audit + remove journal
```

PhotoKit 与 SQLite/向量存储不存在共同事务。`phase` 只描述 Echo 本地 D-005 进度，`sourceDeletionState` 描述外部系统结果；对于 `photoLibraryAndEcho`，后者不是 `confirmedDeleted` 时禁止推进前者。恢复 `prepared` intent 时：full authorized 且资产存在 → `notDeleted`；full authorized 且确认不存在 → `reconciledAbsent` 后转 `confirmedDeleted`；limited 下不可获取或权限 denied/restricted/notDetermined → `indeterminate`，保留 journal 与 Echo 数据并显示 L2。不可见不得等同删除。系统资产确认删除后若 Echo 清理失败，保留可重放日志进入 L2 手动重试或下次前台补偿；不得伪造外部回滚。Share Extension 文本/音频/第三方文件没有来源 App 删除能力，只能执行“仅从 Echo 移除”；音频原件不持久化时只展示转写文本。

外部级联只覆盖 PhotoKit localIdentifier。`PHPhotoLibraryChangeObserver` 投递可验证删除后启动清理，App 启动/前台执行补偿核对；limited-hidden、撤权或受限只标记不可观察，不触发删除。清理无效 ExcludedAssets 时先持久化一次性待提示状态并审计 `userNotified=false`；管理界面实际展示提示后另写 `.excludedAutoCleaned(userNotified=true)`。

#### 5.5.3 可验证引用与系统分享（`4.0i`）

```text
current UserPolicy-filtered generation inputs
  → offline model receives bounded summaries + opaque source identities (UUID or requestAliasV1)
  → versioned JSON envelope {schemaVersion, paragraphs[{text, sourceMemoryIDs[]}]}
  → requestAliasV1: bounded explicit alias lookup → canonical MemoryIDs; text unchanged, unknown alias rejected
  → byte / paragraph / character / reference count limits
  → malformed / unknown-version / oversized: whole generation L2 fail-closed
  → dedupe IDs per paragraph and validate against exact submitted allow-list
  → all valid: cited + [SourceAnchor]
  → none valid: noSource
  → mixed valid/invalid: [SourceAnchor] + partialNoSource
  → tap/preview: current UserPolicy + source resolver revalidation → Detail or honest unavailable

copy / local export / system share intent
  → composition-owned export coordinator
  → PrivacyCheckpoint + current UserPolicy revalidation before reading/preparing payload
  → revoked source: block derived-body handoff and offer return/regeneration
  → allowed but missing/offline source: preserve body; keep unavailable status in App
  → ADR-024 title/body-only plainText / Markdown / multipage PDF payload (no appended source IDs)
  → system share controller actual presentation callback
  → .creationSharePresented(exportFormat, sharePresented=true, shareHandoffIdDigest)
  → dismiss/cancel after presentation: no failure and no target/completion audit
```

allow-list 命中只证明来源身份，不证明来源在语义上蕴含段落事实；UI 不得显示“Verified fact”。严禁按段落位置轮询来源、向模型或导出暴露 `assetID/sourceLocator`、把 payload 就绪当作系统面板已呈现，或把结构化 metadata 塞入 `sourceLanguage`。导出准备或控制器未进入呈现回调即失败时写 `sharePresented=false` 并进入 L2；已呈现后的取消不算失败。若真实呈现后的审计写入失败，保持 `sharePresented=true` 这一事实，显示 L2，并用不含原文/目标 App 的幂等 `PendingOperations` 描述重试。

计数固定为：`sourceMemoryCount` = 当前策略过滤后实际提交模型的唯一 MemoryID 数；`citationCount` = allow-list 校验通过的 anchor occurrence 数（同段重复去重、跨段重复分别计数）；`noSourceCount` = `noSource` 或 `partialNoSource` 段落数。`.synthesis` 与 `.creativeGeneration` 共用生成 traceID 但职责分离；`.creationSharePresented` 使用独立事件，并以 payload UUID 的 hash-only `shareHandoffIdDigest` 精确幂等，禁止最近 N 条扫描或 traceID 复合猜测。完整决策见 ADR-020。

#### 5.5.4 月度/年度报告调度与生成运行时门禁（`4.0j` + `4.0k`）

```text
persisted monthly/yearly switches (new install default on)
  → after durable consent + first canonical memory, persist per-period-type eligibleFrom baselines
launch / foreground / granted BGProcessingTask / explicit user action
  → PrivacyCheckpoint + current UserPolicy/source revalidation
  → this app version configures a production NarrativeReportGenerating capability?
       no: return generationUnavailable before materialization/claim; no report L2/generated audit/report; stop
       yes: continue
  → configured artifact approval / integrity / local loading valid?
       no: L3 model failure; no report materialization/claim/publication; preserve loader audit; stop
       yes: continue
  → materialize completed calendar periods with frozen timezone + UTC boundaries
  → scan only eligible periods; CAS claim at most one earliest key
  → TaskQueueActor enqueue typed, bounded report job
  → ProgressActor persists cursor/algorithm-limit versions, never content or auth snapshots
  → deterministic source-batch plan + token/context/call/memory limits (4.0k)
  → leaf generation: exact submitted leaf IDs, bounded envelope parsing, body-language alignment
  → reduce generation: cited child segments only + their leaf IDs; record omitted coverage
  → typed result dispatch:
       language fallback / generation failure: L2 manual retry, no publication; stop
       cancelled: stop runtime + save checkpoint, no publication; stop
       resource-deferred: release claim, wait for next eligible opportunity; stop
       validated generation: continue
  → revalidate current policy + source content versions; retain all contributing source dependencies
  → PrivacyActor prepares content-free Sendable NarrativeReportAuditPayload (no AuditLog write yet)
  → DatabaseManager no-suspension transaction:
       NarrativeReport + NarrativeReportSource
       + NarrativeReportPeriod.completed
       + payload-backed .narrativeReportGenerated audit row
```

月报标识刚结束的完整公历月，年报标识刚结束的完整公历年；周期键分别为 `month:YYYY-MM` 与 `year:YYYY`。月/年分别持有 `eligibleFrom`，关闭后重开只重设对应类型基线。首次物化保存日历、时区与 `[startInstant, endInstant)` UTC 边界，之后跨时区不重算。只有 `endInstant >` 对应类型基线才物化，该类型首个周期的来源查询从 `max(startInstant, eligibleFrom)` 开始并记录 `partialBaseline`/实际 coverage 起点，禁止读取基线前历史。同一周期唯一且最多成功一次；并发启动/前台/后台扫描由 compare-and-set/revision 排除重复 claim。一次扫描只处理一个周期，相同结束边界先月报后年报。

当前策略下周期内没有任何 canonical memory 时写 `noData` 终态，不生成正文或 `.narrativeReportGenerated`；人物或 HealthKit 等可选输入不可用时省略并在 coverage metadata 标注。所有聚合受版本化 `NarrativeReportLimits` 的来源数、摘录长度、中间层级/数量、模型输入和最终 envelope 上限约束，禁止一次读取全年无界原文或用 fixture 补区块。`4.0j` 只提供可注入 generator seam 和 bounded collection；获批 bundled LLM、生产 adapter 与真正消费 `sourceBatches` 的分批/分层聚合由 `4.0k` 交付。当前运行时缺失时必须返回 `generationUnavailable`，不得物化/claim 周期或写入 `retryRequired`。

ADR-023 补齐执行边界：完整渲染输入经 tokenizer 后满足输入 token + 预留输出 token ≤ 获批 context，推理中强制输出/调用/时间预算；字节/字符上限继续存在。每次调用只获当前输入的叶子 allow-list，未知 ID 降级为 noSource/partialNoSource，畸形/超限 envelope 则整体 L2。语言检测只读解析后的正文，每调用最多一次语言重试；fallback/空输出不算 noData 或成功报告。coverage 按真实已提交来源与完成层数累计，派生依赖不能只取最终显示的锚点。图中 unavailable 表示该版本未装配生成能力；已配置模型加载失败/完整性不通过按 L3 处理，loader 审计与报告 generated 审计分离。

生命周期扫描只自动选择 `eligible`。L2 将周期置为 `retryRequired` 并写 `PendingOperations`，仅用户明确重试；系统后台 expiration、低电量或 serious/critical thermal 则在安全 checkpoint 协作式停止、释放 claim 并回到可调度状态，不冒充 L2。用户取消保留精确 taskId 恢复语义，普通扫描不得接管。系统后台机会采用注册且允许的 `BGProcessingTask`，处理 expiration/completion/resubmission，但不承诺精确执行时刻。

跨进程 Continue 先重验模型/算法/限制/语言与当前输入摘要，再在同 taskId 下重建丢失的内存前缀，保留持久 checkpoint，不把游标当作已存在的中间结果。重放同样消耗本次调用/时间预算，显示重建阶段；身份变化要求合法 Restart，不得复用旧正文，L3/denial 不能被 Restart 绕过。v1 无中间正文持久缓存，不承诺跨硬件或跨进程续接同一 token。详见 ADR-023 §5。

报告正文、标题或来源标识不得进入 TaskProgress、PendingOperations 或 AuditLog。完成报告读取自本地持久层；导航/复制/导出/打印/share 前按 ADR-020 复验当前授权。用户删除报告或删除某 Memory 时，D-005 同步清除相关 `NarrativeReportSource` 与派生报告，并把周期标记为 v1 不可自动/手动重建的 `invalidated`；撤销全部同意时清空 `NarrativeReportSchedule`、报告、周期和恢复/待处理描述。调度/持久化见 ADR-021，生成运行时门禁与任务拆分见 ADR-022。

### 8.1 任务进度存储


### 8.2 进度推送至 UI

`TaskQueueActor` 维护一个 `AsyncStream<ProgressEvent>`，ViewModel 通过 `for await` 订阅。每个 `ProgressEvent` 包含：

- `taskId`
- `taskType`
- `processedCount`
- `totalCount`
- `status` (running/paused/cancelled/completed)

ViewModel 收到事件后更新 `@Observable var progress: Double`，驱动进度条刷新。

### 8.3 跨进程任务重建（Phase 4 `4.0g`）

`TaskProgress` 只保存 `taskId`、raw `taskType`、resume point 与有版本/有上限的值类型 `resumeData`；它不保存 Swift closure、Actor 实例、授权快照、记忆原文或可执行 job。App 重启后的 Continue/Restart 数据流必须经过 composition-owned typed allow-list 任务重建注册表：

1. ResumeProgress adapter 通过恢复协调器读取全部 `TaskProgress` raw 记录，排除当前会话仍由 `TaskQueueActor` 拥有的 taskId，并按精确 taskId 显示每条 orphaned/interrupted 进度；禁止只取同 taskType 最新一条。
2. Continue 数据流：用户点击 → 协调器对 taskId 加单次恢复锁 → allow-list 注册表解析 raw taskType → 校验有版本/有上限的 resumeData → 按当前 UserPolicy 和真实来源授权重新 PrivacyCheckpoint → 构造同类 job → 以“保留旧 checkpoint”模式入队。任一步失败均保留原记录。
3. Restart 数据流：用户点击 → 加单次恢复锁 → 解析 launcher/校验当前权限 → `ProgressActor` 在单一 SQLite 事务中将同 taskId checkpoint 替换为 index 0 可重试记录 → 以“保留已重置 checkpoint”模式入队。SQLite 事务与 Actor 入队是两个可观测阶段，不声称跨边界原子；入队失败保留 index 0 记录供手动重试。
4. Progress 读取必须保留未知 raw taskType；解码为未知、过期或不兼容时返回 L2，保留记录且不执行任意 fallback。重复点击、重复协调器或过期 updatedAt/revision 不得导致双重入队。
5. 只有 `TaskQueueActor` 确认接管 job 后才发布 resumed/restarted，并以结构化非原文字段记录 `.backgroundTaskInterrupted` 的 action、resumePoint、userChoiceOnRestart 与实际结果；taskId/resumeData 仅保留摘要。入队后成功或不可继续最终失败清理 `TaskProgress`，取消/暂停及重建阶段 L2 保留 checkpoint。
6. Pause 保留同一 in-memory job 并在安全点挂起；Cancel 对运行任务先等待协作式终止和最后 checkpoint 写入。未开始且 index 0 的排队任务可直接移除；完成/取消竞态必须只发布一个终态。

## 12. 数据流安全与隐私保障

- **最小化数据暴露**：所有处理均在端侧，无网络上传。原始媒体文件仅引用 PHAsset，不复制。
- **排除表强制执行**：`ExcludedAssetsActor` 在所有导入/同步流程中被前置调用，确保用户排除的内容永不出现。
- **级联删除**：原始文件删除时，`cascadeDeleteFromOriginal` 同时清除向量、索引、排除表记录，并提示用户。
- **审计日志**：所有关键操作（授权变更、记忆删除、模型加载失败等）均有不可篡改的本地审计记录，保留 30 天。
- **deny-by-default 同意闸门（3F.1）**：未同意前 `PrivacyActor.validate()` 返回 PrivacyCheckpoint `.denied`，任何业务数据访问被立即终止（ADR-007 §决策-2）。同意状态流经 `ConsentStoreActor`（SQLite `ConsentStore` 表，版本 + 时间戳）。
- **撤回/清除数据流（3F.1）**：`AppComposition.revokeConsent(boundary:)` → `ConsentStoreActor.revokeConsent` 在单个事务内清除 Memory/Representation/ExcludedAssets/FeedbackStore/TaskProgress/PendingOperations/UserPolicyStore/IndexGeneration/IndexBuildItem/ActiveRouteSet/AuditLog，自擦除审计库；失败回滚并写 `.purgeFailed` 审计，进入 blocked 状态（ADR-007 §决策-3）。
- **审计 hash-only（3F.1）**：`writeAuditLog(content:)` 仅持久化 SHA-256 摘要到 `contentHash` 列，禁止原文（AGENTS.md §5.4）。
- **canonical 事务写入流（3F.4）**：`CanonicalMemoryRepositoryActor.commit` 将 Memory/Representation/MemoryFTS 在单一无挂起点 `executeTransaction`（`DatabaseManager` 同步 BEGIN/COMMIT，杜绝 DEF-50-001 的插入写）中原子提交，再逐 generation 写入 `VectorStoreActor`；任一向量失败触发补偿回滚（删除已写向量 + canonical 行），保证无「向量存在但原文丢失」或「原文存在但无法检索」（US-ING-006 AC-1/2）。确定性记忆 ID 由 `deterministicID(sourceLocator:sourceType:)`（RFC 4122 派生，SHA-256 命名空间，version 5 / variant 8）生成，与摄入顺序无关（ADR-010 决策-1）。
- **全删除边界流（3F.4）**：`deleteMemory` 按 D-005 事务性清除跨全部 generation 的向量 + MemoryFTS + translationCache + canonical 行 + 审计；`writeExcluded=true`（用户「仅从 Echo 移除」）写 ExcludedAssets（US-PRV-004），`false`（级联删除）不写（US-PRV-007）。`cascadeDeleteFromOriginal` 按 sourceLocator 清空关联记忆并清理无效排除记录，审计 `.cascadeDeleteFromOriginal` 含 `excludedWritten=false`。
- **generation 生命周期流（3F.4）**：shadow build（`finishShadowBuild` building→ready）→ `activateGeneration` 原子发布（旧 active 降 `.ready` 并记录为 `previousTextGeneration` 回滚目标，新代 `.active`，版本递增）→ `rollbackToPrevious` 旧代回滚 → `restoreActiveRoute` 启动时按 active route 从 `<generations>/<generationId>.pxkt` 恢复每代存储（维度不匹配重建，杜绝混代服务）。反馈行携带 `generationId`（US-FBK 身份，ADR-010 决策-4）。

## 照片无需手写描述的创作数据流（4.0l / ADR-025，待实现）

PhotoKit 授权摄入 → 原 Memory/视觉检索表示落库 → 用户打开该照片详情或选择创作 → 有界队列读取所选照片真实像素 → 本地画面理解 + 可见文字 OCR → 版本化机器描述/OCR 独立落库 → 当前授权下准备结构化创作素材 → 4.0k 文本生成 → SYN-002 来源验证 → 预览/ADR-024 正文导出。

当前摄入仍为 canonicalText=nil，OCR 搜索向量不包含创作所需正文接线；手写描述测试只证明文本路径。目标流程中新旧照片仅在用户打开该照片详情或选择其进行 AI 创作时按需处理且幂等；导入、同步、前台和自动报告扫描不发起图片理解，手写描述为可选校正。原照片 MemoryID/时间戳不变，机器描述不能冒充原文；来源版本、授权及用户校正改变时旧在途结果不能发布。

报告消费已就绪的派生素材，并记录未准备/失败来源的 coverage；全部待处理照片导致延后而非 noData，L2 不自动重放。补处理不重新打开 completed/invalidated 周期或改变既有 eligibleFrom。全部预算、错误/恢复和删除关系见 ADR-025；未选定/审批视觉模型，不改变当前实现或历史证据。


**照片创作生成门禁（2026-09-09 用户批准）**：允许进入创作页选择模板；所有所选照片必须逐张具备当前有效的 AI 画面描述，或非空白的用户手写描述，才能启用生成。标题、标签、OCR 和来源原文可增强素材，但不能单独满足照片生成门禁。生成管线开始前重新读取当前素材并复核，防止 UI 快照过期或其他入口绕过。准备/失败状态继续提供等待与手动重试，准备完成只启用按钮，不自动生成。
